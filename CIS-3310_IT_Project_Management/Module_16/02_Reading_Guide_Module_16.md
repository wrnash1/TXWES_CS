## Section 2: Domain 1 — Project Management Concepts

### 2.1 Project Characteristics

A project is a temporary endeavor with a defined start and end, undertaken to create
a unique product, service, or result. It differs from operations, which are ongoing
and repetitive.

### 2.2 Project Lifecycle vs. Process Groups

| Concept | Description |
|---|---|
| Project Lifecycle | The phases a project passes through from initiation to closure |
| Process Groups | Initiating, Planning, Executing, Monitoring and Control, Closing — not phases, but groupings of management processes |
| Phase Gate | A formal review at the end of a lifecycle phase to decide whether to proceed |

### 2.3 Organizational Structures

| Structure | PM Authority | Team Assignment | Resource Control |
|---|---|---|---|
| Functional | Low | Borrowed from departments | Functional manager |
| Weak Matrix | Low to moderate | Mostly functional | Functional manager |
| Balanced Matrix | Moderate | Shared | Shared |
| Strong Matrix | Moderate to high | Mostly project-dedicated | PM |
| Projectized | High | Fully dedicated | PM |

### 2.4 Key Roles

| Role | Primary Responsibility |
|---|---|
| Project Sponsor | Authorizes project; provides funding; removes executive barriers |
| Project Manager | Plans, executes, monitors, controls, and closes the project |
| Project Team | Performs the work to produce deliverables |
| Stakeholder | Anyone affected by or who can affect the project |
| PMO | Provides governance standards, templates, and PM support |
| Customer/End User | Receives and uses the project deliverable |

### 2.5 Project Charter

The Project Charter formally authorizes the project and empowers the PM to apply
organizational resources. Key charter contents include project purpose, objectives,
high-level scope, sponsor authorization, PM identification, and initial budget range.

## Section 3: Domain 2 — Project Planning

### 3.1 Work Breakdown Structure

| WBS Concept | Description |
|---|---|
| WBS | Hierarchical decomposition of total project scope into deliverable-oriented components |
| Work Package | Lowest level of the WBS; can be estimated, assigned, and monitored |
| WBS Dictionary | Document defining the content, owner, and acceptance criteria for each WBS element |
| Decomposition | The technique of breaking down deliverables into smaller components |
| 100% Rule | The WBS must capture 100% of the project scope — nothing more, nothing less |

### 3.2 Schedule Development

| Tool or Concept | Description |
|---|---|
| Network Diagram | Shows activity sequence and dependencies; used for CPM and PERT |
| Critical Path | Longest path through the network; determines earliest completion date |
| Float (Slack) | Amount of time an activity can slip without delaying the project end date |
| Critical Path Activities | Have zero float; any delay extends the project |
| FS Dependency | Finish-to-Start: successor cannot start until predecessor finishes |
| SS Dependency | Start-to-Start: successor cannot start until predecessor starts |
| FF Dependency | Finish-to-Finish: successor cannot finish until predecessor finishes |
| SF Dependency | Start-to-Finish: rare; successor cannot finish until predecessor starts |
| Lead | Overlap between activities; negative lag |
| Lag | Delay between activities; forced wait time |

### 3.3 Estimation Techniques

| Technique | Formula or Description |
|---|---|
| Analogous Estimating | Uses historical data from similar projects; top-down; fast but less accurate |
| Parametric Estimating | Uses statistical relationship (e.g., cost per unit times units); more accurate with good data |
| Three-Point (PERT) | (Optimistic + 4 × Most Likely + Pessimistic) / 6 |
| Three-Point (Triangular) | (Optimistic + Most Likely + Pessimistic) / 3 |
| Bottom-Up Estimating | Estimates each work package individually then rolls up; most accurate; most time-consuming |
| Reserve Analysis | Adds contingency reserve for known risks; management reserve for unknown unknowns |

### 3.4 Earned Value Management Formulas

| Formula | Calculation | Interpretation |
|---|---|---|
| SV (Schedule Variance) | EV − PV | Positive = ahead of schedule |
| CV (Cost Variance) | EV − AC | Positive = under budget |
| SPI (Schedule Performance Index) | EV / PV | Greater than 1.0 = ahead of schedule |
| CPI (Cost Performance Index) | EV / AC | Greater than 1.0 = under budget |
| EAC (Estimate at Completion) | BAC / CPI | Projected total cost at current efficiency |
| ETC (Estimate to Complete) | EAC − AC | Remaining work cost projection |
| VAC (Variance at Completion) | BAC − EAC | Positive = will finish under budget |
| TCPI (To-Complete Performance Index) | (BAC − EV) / (BAC − AC) | Efficiency needed to finish on original budget |

### 3.5 Risk Management

| Process | Key Output |
|---|---|
| Identify Risks | Risk Register |
| Qualitative Risk Analysis | Probability-Impact Matrix; risk prioritization |
| Quantitative Risk Analysis | Expected Monetary Value; Monte Carlo simulation |
| Plan Risk Responses | Risk response strategies per risk |
| Monitor Risks | Risk reassessment; residual and secondary risks |

Risk response strategies for threats: Avoid, Transfer, Mitigate, Accept.

Risk response strategies for opportunities: Exploit, Share, Enhance, Accept.

Residual risk: risk remaining after a response is applied. Secondary risk: new risk
created by implementing a risk response.

### 3.6 Communication Planning

Communication channels formula: N × (N − 1) / 2, where N = number of stakeholders.

| Stakeholders | Communication Channels |
|---|---|
| 5 | 10 |
| 10 | 45 |
| 15 | 105 |
| 20 | 190 |

The Communication Management Plan documents who needs what information, when, and
through what channel. It is produced during planning and updated throughout the project.

## Section 4: Domain 3 — Project Execution and Delivery

### 4.1 Team Development and Motivation

| Model | Key Concept |
|---|---|
| Tuckman Model | Forming → Storming → Norming → Performing → Adjourning |
| Maslow's Hierarchy | Physiological → Safety → Social → Esteem → Self-Actualization |
| Herzberg Two-Factor | Hygiene factors prevent dissatisfaction; motivators drive satisfaction |
| McGregor Theory X | Workers dislike work; need control and direction |
| McGregor Theory Y | Workers are self-motivated; seek responsibility |
| McClelland's Theory | Achievement, affiliation, and power as core motivators |

### 4.2 Conflict Resolution Methods (Priority Order)

1. Collaborate / Problem Solve — address root cause; best long-term outcome
2. Compromise / Reconcile — both parties give something; acceptable outcome
3. Accommodate / Smooth — give in; preserves relationship; does not resolve issue
4. Avoid / Withdraw — delay or retreat; issue remains unresolved
5. Force / Direct — impose a decision; may create resentment; last resort

### 4.3 Quality Management

| Process | Type | Focus |
|---|---|---|
| Quality Planning | Proactive | Define quality standards and how to achieve them |
| Quality Assurance (QA) | Proactive | Audit processes to ensure standards are being followed |
| Quality Control (QC) | Reactive | Inspect outputs against standards; identify defects |

Cost of Quality categories: prevention costs, appraisal costs, internal failure costs,
external failure costs. Prevention is always the least expensive over the full project lifecycle.

### 4.4 Contract Types Summary

| Type | Risk Bearer | Best Used When |
|---|---|---|
| FFP | Seller | Requirements fully defined |
| FPIF | Seller (with shared incentive) | Defined scope; performance incentive desired |
| FP-EPA | Seller | Long contract; inflation risk |
| T&M | Shared (buyer if no ceiling) | Scope uncertain; consulting or staff augmentation |
| CPFF | Buyer | R&D; highly uncertain scope |
| CPIF | Shared | Cost incentive alignment needed |
| CPAF | Buyer | Government; subjective performance evaluation |

### 4.5 Agile Execution Reference

| Framework | Key Characteristics |
|---|---|
| Scrum | Sprints (1–4 weeks); three roles; five events; three artifacts |
| Kanban | Continuous flow; WIP limits; no fixed sprints |
| Hybrid | Combines waterfall structure with Agile delivery |

Scrum roles: Product Owner (backlog), Scrum Master (facilitation), Developers (delivery).

Scrum events: Sprint, Sprint Planning, Daily Scrum (15 min), Sprint Review, Sprint Retrospective.

Scrum artifacts: Product Backlog, Sprint Backlog, Product Increment.

Velocity = average story points completed per sprint. Used for forecasting, not performance scoring.

Definition of Done = shared quality criteria every increment must meet.

## Section 5: Domain 4 — Change, Control, and Communication

### 5.1 Integrated Change Control

All project changes must go through the Integrated Change Control (ICC) process:

1. Change request submitted in writing
2. Impact assessed across scope, schedule, cost, quality, and risk
3. Change Control Board (CCB) reviews and decides
4. If approved, project management plan updated; stakeholders notified
5. If rejected, change request documented and filed

No verbal change authorizations. No unilateral scope changes.

### 5.2 Baselines

| Baseline | What It Covers |
|---|---|
| Scope Baseline | Approved project scope statement + WBS + WBS Dictionary |
| Schedule Baseline | Approved project schedule |
| Cost Baseline | Approved budget over time (S-curve) |
| Performance Measurement Baseline | Scope + schedule + cost integrated baseline for EVM |

Baselines can only be changed through the formal change control process.

### 5.3 Reporting Types

| Report Type | Purpose |
|---|---|
| Status Report | Current state at a point in time |
| Progress Report | Work completed to date; cumulative performance |
| Forecast Report | Projected future performance based on trends |
| Variance Report | Deviation of actual from planned performance |
| Lessons Learned | Documented knowledge from project experience |

## Section 6: Domain 5 — Project Closing

### 6.1 Administrative Closure

Administrative closure formalizes the end of the project. Key activities:

- Obtain formal written acceptance from the customer or sponsor
- Archive all project records in organizational process assets
- Update organizational process assets with lessons learned
- Release team members and project resources
- Complete final performance reports

### 6.2 Procurement Closure

Each contract must be formally closed independently. Steps:

1. Verify all deliverables accepted against acceptance criteria
2. Authorize and process final payment
3. Archive contract records
4. Document vendor performance evaluation
5. Notify legal and finance of contract closure

### 6.3 Lessons Learned

Lessons learned are captured throughout the project (not only at closure) and stored
in the lessons learned register. They are inputs to future project planning and
organizational process improvement. In Agile environments, retrospectives serve the
same purpose within each sprint.

### 6.4 Transition and Knowledge Transfer

Project closure includes transitioning the deliverable to operational ownership. This
requires training end users and operational staff, delivering complete documentation,
establishing support and maintenance arrangements, and obtaining sign-off from the
receiving operations team.

## Section 7: Exam Strategy Reference

### 7.1 Question Stem Keywords

| Keyword | What to Focus On |
|---|---|
| "First" | Process sequence; what comes before everything else |
| "Next" | The immediately following step in the process |
| "Best" | Most appropriate given the scenario's constraints |
| "Least likely" | Eliminate the clearly correct answers; find the exception |
| "Most likely" | The primary or most common cause or effect |

### 7.2 High-Frequency Exam Traps

| Trap | Correct Thinking |
|---|---|
| Change request arrives — do what first? | Assess the impact before approving or rejecting |
| Stakeholder wants something added — what do you do? | Submit a change request through ICC |
| Conflict on the team — best first response? | Collaborate / Problem Solve |
| New team member joins — what must be updated? | Communication Management Plan (channels formula changes) |
| Project in trouble on cost — what metric confirms? | CPI less than 1.0 |
| PM needs authority to start a project — what document? | Project Charter |
| Vendor delivers late — what document governs? | Contract (SOW + terms) |
