### Introduction
Welcome to **Module 03 - Scope Management – WBS and Scope Statement**! Scope is the foundation of every project plan: if you don't know exactly what work is (and is not) included, you cannot reliably estimate time or cost. This module covers how to formally define scope through a Scope Statement, how to decompose that scope into manageable pieces using a Work Breakdown Structure (WBS), and how to prevent unauthorized scope additions (scope creep) through rigorous scope control.

These topics represent some of the highest-density exam content on both CompTIA Project+ and PMI CAPM. Expect scenario-based questions asking you to identify the correct artifact, recognize symptoms of scope creep, or choose the best decomposition strategy.

---

### 1. High-Yield Glossary
Review these essential definitions carefully. The certification exam expects you to know these concepts inside and out:

*   **Work Breakdown Structure (WBS)**: A hierarchical decomposition of the total project scope into smaller, more manageable components. The WBS organizes all project work into deliverable-oriented groups, with the project itself at the top, major deliverables at the second level, and increasingly detailed sub-deliverables and work packages below. Every element of project work must appear somewhere in the WBS—this is called "100% Rule."
*   **Decomposition**: The technique of breaking down project deliverables and project work into smaller, more manageable components. Decomposition continues until each component is small enough to be reliably estimated, scheduled, and assigned to a single team or individual. The lowest level of decomposition in a WBS is called a work package.
*   **Work Packages**: The lowest-level components in a WBS, representing units of work that can be scheduled, cost-estimated, monitored, and controlled. Work packages are the building blocks for creating activity lists and schedule estimates. They are small enough that a single person or team can own them, but not so small that tracking them adds unnecessary overhead.
*   **Scope Creep**: The uncontrolled expansion of project scope without corresponding adjustments to schedule, budget, or resources. Scope creep typically occurs when stakeholders add requirements informally (outside the change control process) and the project team begins implementing them without proper authorization. It is a leading cause of project failure.
*   **WBS Dictionary**: A companion document to the WBS that provides detailed information about each WBS component, including the description of work, responsible party, milestones, quality requirements, and acceptance criteria. Think of the WBS as a visual outline and the WBS Dictionary as its detailed definitions.

### 2. Certification Exam Tips
*   **Project+ Tip – The 100% Rule**: Every piece of project work must appear in the WBS, and nothing outside the project scope should appear. Exam questions will test whether you can identify WBS violations—work missing from the WBS, or work in the WBS that is outside the approved scope.
*   **CAPM Tip – WBS vs. Activity List**: The WBS ends at work packages; the Activity List is derived from work packages by further breaking them into schedule activities. The CAPM exam distinguishes between these two outputs—the WBS is a scope tool, the Activity List is a schedule tool.
*   **Scenario Trap**: If a question describes a team member adding features or changes without a formal change request, the situation is scope creep. The correct PM response is to stop the unauthorized work and route it through the change control process—not to accept it or simply document it after the fact.

### Lab & Command Integration
In this week's hands-on lab, you will perform the following steps to apply these concepts:
*   **Decompose a software project into WBS levels**: Using a provided IT software deployment scenario, build a 3-level WBS hierarchy identifying at least three major deliverable categories and their associated sub-deliverables.
