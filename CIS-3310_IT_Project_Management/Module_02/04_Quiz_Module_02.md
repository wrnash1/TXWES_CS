## Question 1

Which document authorizes the formal existence of a project and gives the project manager authority to apply resources?

- A) Project Scope Statement
- B) Project Charter
- C) Work Breakdown Structure
- D) Statement of Work

Correct Answer: B) The Project Charter is signed by the project sponsor during the Initiating Process Group to formally authorize the project and grant the PM authority to commit resources.

Distractor Analysis:

- *Why B is correct:* The Project Charter is the definitive authorization document in PMI methodology. It names the PM and grants them authority over organizational resources. No other document serves this function.
- *Why A is incorrect:* The Scope Statement defines the project's deliverables and boundaries — it is a Planning output, not an authorization document.
- *Why C is incorrect:* The WBS is a scope decomposition tool created in the Planning Process Group; it defines work, not authority.
- *Why D is incorrect:* A Statement of Work describes the work to be performed (often in a procurement context) but does not formally authorize a project or grant PM authority over organizational resources.

## Question 2

Which of the following best defines a Stakeholder Register in project management?

- A) A project document that records all identified stakeholders, including their roles, interests, influence levels, and engagement strategies.
- B) A financial spreadsheet used to track project expenditures against the approved budget baseline.
- C) A schedule artifact that lists all project activities, their durations, and assigned resources.
- D) A contract document signed by vendors before they begin delivering goods or services to the project.

Correct Answer: A) A project document that records all identified stakeholders, including their roles, interests, influence levels, and engagement strategies.

Distractor Analysis:

- *Why A is correct:* The Stakeholder Register is a living document created during Initiating and updated throughout the project. It captures who the stakeholders are, what they want, and how the PM should engage them.
- *Why B is incorrect:* Tracking expenditures against a budget describes the cost management plan or a budget baseline — a different document entirely.
- *Why C is incorrect:* Listing activities, durations, and resources describes an activity list or resource management plan, not a stakeholder register.
- *Why D is incorrect:* A vendor agreement is a contract or purchase order, part of Procurement Management, not stakeholder documentation.

## Question 3

A project sponsor tells the project manager to begin work immediately on a new software deployment before the project charter has been approved. What is the best response?

- A) Begin work immediately to meet the sponsor's deadline; the charter can be signed later.
- B) Politely explain that formal project authorization via a signed charter is required before committing resources, and request expedited approval.
- C) Escalate the situation to senior IT leadership and pause all communication with the sponsor.
- D) Start work but keep no records until the charter is signed to avoid liability.

Correct Answer: B) Politely explain that formal project authorization via a signed charter is required before committing resources, and request expedited approval.

Distractor Analysis:

- *Why B is correct:* PMI methodology requires a signed charter before work begins. Beginning work without authorization exposes the organization to uncontrolled costs, undefined scope, and legal risk. The correct approach is to expedite approval, not bypass it.
- *Why A is incorrect:* Beginning unauthorized work is a recognized PM antipattern. It creates scope and budget accountability problems.
- *Why C is incorrect:* Escalating immediately and halting communication is an overreaction. The PM should first discuss the authorization requirement directly with the sponsor.
- *Why D is incorrect:* Keeping no records creates serious governance and audit problems — this approach is never recommended.

## Question 4

During which PMI Process Group is the Project Management Plan created?

- A) Initiating
- B) Planning
- C) Executing
- D) Closing

Correct Answer: B) The Project Management Plan is the primary output of the Planning Process Group and serves as the guide for executing and controlling the project.

Distractor Analysis:

- *Why B is correct:* Planning produces the Project Management Plan, which integrates subsidiary plans for scope, schedule, cost, quality, resources, communications, risk, procurement, and stakeholders.
- *Why A is incorrect:* Initiating produces the Project Charter and Stakeholder Register, not the detailed management plan.
- *Why C is incorrect:* Executing carries out the work defined in the plan; it does not create the plan itself.
- *Why D is incorrect:* Closing formalizes project completion, archives documents, and releases resources; it does not create a management plan.

## Question 5

A business analyst completes a cost-benefit analysis recommending a cloud migration project based on projected three-year savings. Which project initiation document does this analysis most directly support?

- A) Risk Register
- B) Project Schedule
- C) Business Case
- D) Change Request Form

Correct Answer: C) A Business Case justifies the investment in a project by documenting expected benefits, costs, risks, and the recommended option.

Distractor Analysis:

- *Why C is correct:* The Business Case is prepared before or during project initiation to justify why the project should be approved and funded. A cost-benefit analysis is a core component of the Business Case.
- *Why A is incorrect:* A Risk Register identifies and analyzes risks after the project is approved; it does not justify the initial investment.
- *Why B is incorrect:* A Project Schedule defines the timeline for approved project work; it is created during Planning, not as a justification for starting the project.
- *Why D is incorrect:* A Change Request Form is used to request modifications to an already-approved, in-progress project — not to propose a new project.

## Question 6

The Monitoring and Controlling Process Group is best described as running:

- A) Only at the end of each lifecycle phase, after Executing is complete
- B) Once at the midpoint of the project to check status
- C) Continuously throughout the project, in parallel with Executing
- D) Only during the Planning Process Group to review the plan before work begins

Correct Answer: C) Continuously throughout the project, in parallel with Executing.

Distractor Analysis:

- *Why C is correct:* Monitoring and Controlling is an ongoing activity. From the moment work begins, the PM is simultaneously tracking performance, comparing to baselines, and taking corrective action. It does not start and stop — it runs in parallel with Executing.
- *Why A is incorrect:* Waiting until after Executing to monitor is too late. Variances discovered after execution is complete cannot be corrected. M&C must be active while work is happening.
- *Why B is incorrect:* A midpoint check is far too infrequent. M&C processes are applied continuously — on a daily or weekly basis in most projects.
- *Why D is incorrect:* M&C does not occur during Planning. Planning creates the baselines that M&C will later compare actual performance against.

## Question 7

In a predictive (Waterfall) lifecycle, when should the project team begin executing work?

- A) As soon as the Project Charter is signed, to avoid wasting time
- B) After the Project Management Plan is approved and the scope baseline is established
- C) Simultaneously with Planning, to save time on large projects
- D) After the first sprint review reveals what needs to be built

Correct Answer: B) After the Project Management Plan is approved and the scope baseline is established.

Distractor Analysis:

- *Why B is correct:* In a predictive lifecycle, Planning must be substantially complete before Executing begins. The Project Management Plan, including the scope, schedule, and cost baselines, provides the foundation the team needs to do the work correctly.
- *Why A is incorrect:* The charter authorizes initiation, not execution. Starting work immediately after the charter is signed skips the Planning Process Group and creates uncontrolled execution.
- *Why C is incorrect:* Running Planning and Executing simultaneously is an Agile/iterative concept, not appropriate for a predictive lifecycle where full upfront planning is the foundation.
- *Why D is incorrect:* Sprint reviews are an Agile/Scrum concept. In a predictive lifecycle there are no sprints — the scope is defined before any work begins.

## Question 8

Which Process Group produces the Lessons Learned Register?

- A) Initiating
- B) Planning
- C) Executing
- D) Closing

Correct Answer: D) The Lessons Learned Register is formally produced during the Closing Process Group, though lessons should be captured throughout the project.

Distractor Analysis:

- *Why D is correct:* The formal Lessons Learned Register is a Closing output. It documents what the project team learned — successes to repeat and failures to avoid — and stores that knowledge as an Organizational Process Asset.
- *Why A is incorrect:* Initiating produces the Project Charter and Stakeholder Register. No lessons learned document exists at project start.
- *Why B is incorrect:* Planning creates management plans and baselines; lessons learned from prior projects may be consulted as OPAs during Planning, but a new register is not created then.
- *Why C is incorrect:* While lessons should be captured informally during execution, the formal register is a Closing output. Naming Executing as the answer misses the formal documentation step.

## Question 9

A multi-phase IT program is structured into three phases: Design, Build, and Deploy. In which phases does the Initiating Process Group occur?

- A) Only in Phase 1 (Design), since the project was already authorized at the start
- B) At the beginning of each phase — Initiating activities occur in all three phases
- C) Only in Phase 3 (Deploy), since that is when delivery is formally authorized
- D) Initiating does not apply to multi-phase projects; only Planning and Executing apply

Correct Answer: B) At the beginning of each phase — Initiating activities occur in all three phases.

Distractor Analysis:

- *Why B is correct:* In multi-phase projects, each phase typically begins with Initiating activities (re-authorizing the next phase, updating the stakeholder register, confirming the PM's authority to proceed). This is why the Process Groups are described as repeating, not as a one-time linear sequence.
- *Why A is incorrect:* While the overall project may be authorized once, each phase in a phased approach often requires its own go/no-go decision and phase-level authorization.
- *Why C is incorrect:* Deploy is the final phase; it does not authorize the work in Design or Build. Initiating applies at the beginning of each phase, not only the last one.
- *Why D is incorrect:* All five Process Groups apply to multi-phase projects. The Process Group framework is universal — it is never suspended for complex or multi-phase work.

## Question 10

An IT project manager discovers that the project is three weeks behind schedule and $20,000 over budget during a routine performance review. She recommends adjusting the schedule baseline and submitting additional funding for approval. In which Process Group is she working?

- A) Planning — because she is revising the project plan
- B) Executing — because she is managing the team's work
- C) Monitoring and Controlling — because she is measuring performance and initiating a change request
- D) Closing — because she is resolving final project issues

Correct Answer: C) Monitoring and Controlling — because she is measuring performance and initiating a change request.

Distractor Analysis:

- *Why C is correct:* Comparing actual performance to the baseline (discovering the variance) and recommending corrective action (submitting a change request) are the defining activities of Monitoring and Controlling.
- *Why A is incorrect:* Revising the plan is triggered by M&C findings, but the initial detection and response recommendation happen in M&C, not Planning. Planning created the original baseline being compared against.
- *Why B is incorrect:* Executing is where the team does the project work. The PM's performance review and variance response are M&C activities, not Executing activities.
- *Why D is incorrect:* Closing occurs only at the end of the project after deliverables are accepted. A mid-project performance issue has nothing to do with Closing.
