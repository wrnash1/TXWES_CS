**Question 1**
In database design, which key uniquely identifies each row within its own table?
*   A) Foreign Key
*   B) Primary Key
*   C) Candidate Key
*   D) Composite Key
*   **Correct Answer:** B) A Primary Key enforces entity integrity by uniquely identifying every row in a table — no duplicate values and no nulls are permitted.
*   **Distractor Analysis:**
    *   *Why correct:* A Primary Key enforces entity integrity by uniquely identifying every row in a table.
    *   Foreign keys link rows across separate tables. Candidate keys are eligible columns, but only one becomes the primary key.

**Question 2**
In data analytics, which of the following most accurately defines a **foreign key**?
*   A) A column (or set of columns) in one table that references the primary key in another table, enforcing referential integrity between the two tables.
*   B) A key that is automatically generated by the database engine and increments by one for each new row inserted.
*   C) A composite identifier made up of two or more columns that together uniquely identify a row when no single column is sufficient.
*   D) A temporary index created at query time to speed up a specific JOIN operation and discarded after the query completes.
*   **Correct Answer:** A) A column (or set of columns) in one table that references the primary key in another table, enforcing referential integrity between the two tables.
*   **Distractor Analysis:**
    *   *Why A is correct:* This is the precise definition of a foreign key — it creates the link between tables and prevents orphaned records.
    *   *Why B is incorrect:* An auto-incrementing column describes a surrogate primary key or identity column, not a foreign key.
    *   *Why C is incorrect:* This describes a composite key, which can be a primary key but is not a foreign key.
    *   *Why D is incorrect:* Foreign keys are permanent schema constraints, not temporary query-time indexes.

**Question 3**
A retail company wants to design a data warehouse for fast sales reporting. The requirements emphasize query speed and simplicity over storage efficiency. Which schema design best meets these requirements?
*   A) Snowflake schema, because normalized dimension tables reduce JOIN complexity.
*   B) Star schema, because the central fact table connects directly to denormalized dimension tables, minimizing JOIN depth for typical BI queries.
*   C) Third normal form (3NF) schema, because full normalization always produces the fastest query performance.
*   D) Entity-relationship (ER) schema, because it is the standard for all data warehouse implementations.
*   **Correct Answer:** B) Star schema, because the central fact table connects directly to denormalized dimension tables, minimizing JOIN depth for typical BI queries.
*   **Distractor Analysis:**
    *   *Why B is correct:* Star schemas trade storage efficiency for query speed — fewer JOINs mean faster BI dashboard queries.
    *   *Why A is incorrect:* Snowflake schemas normalize dimensions into sub-tables, which increases JOIN complexity and can slow queries.
    *   *Why C is incorrect:* 3NF reduces redundancy but increases the number of JOINs required, which typically slows analytical queries.
    *   *Why D is incorrect:* ER schemas describe entity relationships in operational databases and are not a data warehouse schema pattern.

**Question 4**
A data analyst needs to pull customer records from an external e-commerce platform's public API to supplement internal sales data. What type of data source is this, and what is the primary risk?
*   A) First-party data; risk of internal data governance violations.
*   B) Third-party data; risk of inconsistent data quality, format changes, and privacy compliance concerns.
*   C) Second-party data; risk of exceeding the database connection pool limit.
*   D) Structured data; risk that the JSON response cannot be loaded into any analytical tool.
*   **Correct Answer:** B) Third-party data; risk of inconsistent data quality, format changes, and privacy compliance concerns.
*   **Distractor Analysis:**
    *   *Why B is correct:* A public API from an external platform with no direct business partnership is third-party data. Quality, schema stability, and privacy compliance (GDPR, CCPA) are all risks.
    *   *Why A is incorrect:* First-party data is collected directly by the organization from its own users — an external API does not qualify.
    *   *Why C is incorrect:* Second-party data requires a direct data-sharing agreement with a partner; a public API without such an agreement is third-party.
    *   *Why D is incorrect:* JSON from an API is semi-structured and can be parsed by standard analytics tools; the format alone is not the primary risk.

**Question 5**
A database administrator notices that deleting a record from the `Customers` table causes related records in the `Orders` table to reference a customer that no longer exists. Which constraint should be implemented to prevent this?
*   A) A NOT NULL constraint on the Orders table primary key.
*   B) A UNIQUE constraint on the customer email column.
*   C) A FOREIGN KEY constraint with ON DELETE CASCADE or RESTRICT to maintain referential integrity.
*   D) A CHECK constraint that validates the order total is greater than zero.
*   **Correct Answer:** C) A FOREIGN KEY constraint with ON DELETE CASCADE or RESTRICT to maintain referential integrity.
*   **Distractor Analysis:**
    *   *Why C is correct:* Orphaned records result from missing referential integrity enforcement. A foreign key with CASCADE or RESTRICT prevents deletes that would leave child records without a valid parent.
    *   *Why A is incorrect:* A NOT NULL constraint only prevents empty primary key values; it does not link tables or prevent orphaned records.
    *   *Why B is incorrect:* A UNIQUE constraint prevents duplicate email values but has no effect on cross-table record dependencies.
    *   *Why D is incorrect:* A CHECK constraint validates a column value against a rule; it cannot detect or prevent orphaned cross-table references.
