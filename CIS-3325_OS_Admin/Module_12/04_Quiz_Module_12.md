**Question 1**
An administrator on a systemd-based Linux server wants to view all log entries generated by the `nginx` service since the last system boot. Which `journalctl` command is correct?
A) journalctl -u nginx --since boot
B) journalctl -u nginx -b
C) journalctl --service=nginx --boot
D) journalctl -f nginx
*   **Correct Answer:** B) journalctl -u nginx -b
*   **Distractor Analysis:**
    *   *Why A is incorrect:* `--since boot` is not a valid `journalctl` flag combination. The correct flag to filter by boot is `-b` (or `--boot`). `--since` takes a timestamp string such as `"today"` or `"2026-05-01 08:00:00"`, not the keyword `boot`.
    *   *Why C is incorrect:* `--service` is not a valid `journalctl` option. The correct flag for filtering by systemd unit name is `-u` (or `--unit`). The `--boot` flag without a value is equivalent to `-b 0` (current boot), which is valid, but `--service` makes the whole command invalid.
    *   *Why D is incorrect:* `journalctl -f` follows the journal in real time (like `tail -f`) and does not accept a service name as a positional argument. To follow a specific unit in real time the correct syntax is `journalctl -f -u nginx`.

**Question 2**
A security administrator needs to determine which file on a RHEL 9 server contains SSH authentication events and failed login attempts. Which log file is correct?
A) /var/log/auth.log
B) /var/log/syslog
C) /var/log/secure
D) /var/log/audit/audit.log
*   **Correct Answer:** C) /var/log/secure
*   **Distractor Analysis:**
    *   *Why A is incorrect:* `/var/log/auth.log` is the authentication log file on Debian-based distributions such as Ubuntu. On RHEL, CentOS, and Fedora, authentication messages are written to `/var/log/secure` instead.
    *   *Why B is incorrect:* `/var/log/syslog` is the general-purpose system log on Debian/Ubuntu systems. On RHEL it is `/var/log/messages`. Neither is the dedicated authentication log — SSH login events are specifically routed to the auth facility, which maps to `/var/log/secure` on RHEL.
    *   *Why D is incorrect:* `/var/log/audit/audit.log` is written by the Linux Audit daemon (`auditd`) and contains SELinux events, syscall records, and policy violations. While it can record authentication events if audit rules are configured for them, it is not the primary log for routine SSH login attempts — that is `/var/log/secure`.

**Question 3**
An administrator notices that after each server reboot, the systemd journal contains no entries from before the reboot. They want log entries to persist across reboots. What is the simplest fix?
A) Set `ForwardToSyslog=yes` in `/etc/systemd/journald.conf` and restart rsyslog.
B) Create the directory `/var/log/journal/` and restart the `systemd-journald` service.
C) Install the `logrotate` package and configure a daily rotation schedule for journal files.
D) Edit `/etc/rsyslog.conf` to add `*.* /var/log/journal` as a log destination.
*   **Correct Answer:** B) Create the directory `/var/log/journal/` and restart the `systemd-journald` service.
*   **Distractor Analysis:**
    *   *Why A is incorrect:* `ForwardToSyslog=yes` causes `journald` to forward messages to rsyslog, enabling rsyslog to write them to text files. This is a workaround for persistence via rsyslog, not direct journal persistence. Creating `/var/log/journal/` is simpler and the standard method for making the native journal persistent.
    *   *Why C is incorrect:* `logrotate` manages rotation and compression of existing log files — it does not affect whether the journal stores data in volatile RAM or persistent disk. It has no ability to make `journald` write to disk.
    *   *Why D is incorrect:* `/var/log/journal` as an rsyslog destination is not a valid rsyslog configuration path for journal persistence. rsyslog writes text files; journal storage is a separate binary store managed entirely by `systemd-journald`, not rsyslog.

**Question 4**
A systems administrator runs `vmstat 1 5` and observes that the `wa` column consistently shows values of 40–60 across all five samples. What does this indicate?
A) The system's run queue is full and processes are waiting for CPU time.
B) The system is spending 40–60% of CPU time waiting for I/O operations to complete, indicating a disk bottleneck.
C) Swap utilization is at 40–60%, indicating the system is low on physical RAM.
D) The network interface is 40–60% saturated, causing packet drops and high latency.
*   **Correct Answer:** B) The system is spending 40–60% of CPU time waiting for I/O operations to complete, indicating a disk bottleneck.
*   **Distractor Analysis:**
    *   *Why A is incorrect:* The run queue length is shown in the `r` column of `vmstat`, not `wa`. A high `r` value relative to CPU count indicates CPU saturation. The `wa` column specifically measures I/O wait time.
    *   *Why C is incorrect:* Swap utilization is shown in the `si` (swap-in) and `so` (swap-out) columns. Non-zero `si`/`so` values indicate memory pressure causing swapping. The `wa` column is unrelated to swap usage levels.
    *   *Why D is incorrect:* `vmstat` does not report network interface utilization. Network statistics are viewed with tools like `ip -s link`, `sar -n DEV`, or `netstat -s`. The `wa` column is strictly a CPU metric measuring time blocked waiting on disk I/O.

**Question 5**
An administrator wants to view only log messages at `err` priority and higher (critical, alert, emergency) from the current boot using `journalctl`. Which command is correct?
A) journalctl -b -p err
B) journalctl -b --level=error
C) journalctl -b -t err
D) journalctl -b -u err
*   **Correct Answer:** A) journalctl -b -p err
*   **Distractor Analysis:**
    *   *Why B is incorrect:* `--level` is not a valid `journalctl` option. The correct flag for filtering by syslog priority is `-p` (or `--priority`). This command would fail with an unrecognized option error.
    *   *Why C is incorrect:* The `-t` flag filters by syslog identifier (the program name that generated the message), not by priority level. `journalctl -b -t err` would attempt to find messages from a program named `err`, returning no results.
    *   *Why D is incorrect:* The `-u` flag filters by systemd unit name. `journalctl -b -u err` would search for a service unit named `err`, which does not exist. It is not a priority filter.
