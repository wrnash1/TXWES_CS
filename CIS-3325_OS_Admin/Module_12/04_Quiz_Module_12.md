### Question 1

An administrator on a systemd-based Linux server wants to view all log entries generated by the `nginx` service since the last system boot. Which `journalctl` command is correct?

- A) journalctl -u nginx --since boot
- B) journalctl -u nginx -b
- C) journalctl --service=nginx --boot
- D) journalctl -f nginx

Correct Answer: B) journalctl -u nginx -b

Distractor Analysis:

- Why A is incorrect: `--since boot` is not a valid `journalctl` flag combination. The correct flag to filter by boot is `-b` (or `--boot`). `--since` takes a timestamp string such as `"today"` or `"2026-05-01 08:00:00"`, not the keyword `boot`.
- Why C is incorrect: `--service` is not a valid `journalctl` option. The correct flag for filtering by systemd unit name is `-u` (or `--unit`). The `--boot` flag without a value is equivalent to `-b 0` (current boot), which is valid, but `--service` makes the whole command invalid.
- Why D is incorrect: `journalctl -f` follows the journal in real time (like `tail -f`) and does not accept a service name as a positional argument. To follow a specific unit in real time the correct syntax is `journalctl -f -u nginx`.

### Question 2

A security administrator needs to determine which file on a RHEL 9 server contains SSH authentication events and failed login attempts. Which log file is correct?

- A) /var/log/auth.log
- B) /var/log/syslog
- C) /var/log/secure
- D) /var/log/audit/audit.log

Correct Answer: C) /var/log/secure

Distractor Analysis:

- Why A is incorrect: `/var/log/auth.log` is the authentication log file on Debian-based distributions such as Ubuntu. On RHEL, CentOS, and Fedora, authentication messages are written to `/var/log/secure` instead.
- Why B is incorrect: `/var/log/syslog` is the general-purpose system log on Debian/Ubuntu systems. On RHEL it is `/var/log/messages`. Neither is the dedicated authentication log — SSH login events are specifically routed to the auth facility, which maps to `/var/log/secure` on RHEL.
- Why D is incorrect: `/var/log/audit/audit.log` is written by the Linux Audit daemon (`auditd`) and contains SELinux events, syscall records, and policy violations. While it can record authentication events if audit rules are configured for them, it is not the primary log for routine SSH login attempts — that is `/var/log/secure`.

### Question 3

An administrator notices that after each server reboot, the systemd journal contains no entries from before the reboot. They want log entries to persist across reboots. What is the simplest fix?

- A) Set `ForwardToSyslog=yes` in `/etc/systemd/journald.conf` and restart rsyslog.
- B) Create the directory `/var/log/journal/` and restart the `systemd-journald` service.
- C) Install the `logrotate` package and configure a daily rotation schedule for journal files.
- D) Edit `/etc/rsyslog.conf` to add `*.* /var/log/journal` as a log destination.

Correct Answer: B) Create the directory `/var/log/journal/` and restart the `systemd-journald` service.

Distractor Analysis:

- Why A is incorrect: `ForwardToSyslog=yes` causes `journald` to forward messages to rsyslog, enabling rsyslog to write them to text files. This is a workaround for persistence via rsyslog, not direct journal persistence. Creating `/var/log/journal/` is simpler and the standard method for making the native journal persistent.
- Why C is incorrect: `logrotate` manages rotation and compression of existing log files — it does not affect whether the journal stores data in volatile RAM or persistent disk. It has no ability to make `journald` write to disk.
- Why D is incorrect: `/var/log/journal` as an rsyslog destination is not a valid rsyslog configuration path for journal persistence. rsyslog writes text files; journal storage is a separate binary store managed entirely by `systemd-journald`, not rsyslog.

### Question 4

A systems administrator runs `vmstat 1 5` and observes that the `wa` column consistently shows values of 40-60 across all five samples. What does this indicate?

- A) The system's run queue is full and processes are waiting for CPU time.
- B) The system is spending 40-60% of CPU time waiting for I/O operations to complete, indicating a disk bottleneck.
- C) Swap utilization is at 40-60%, indicating the system is low on physical RAM.
- D) The network interface is 40-60% saturated, causing packet drops and high latency.

Correct Answer: B) The system is spending 40-60% of CPU time waiting for I/O operations to complete, indicating a disk bottleneck.

Distractor Analysis:

- Why A is incorrect: The run queue length is shown in the `r` column of `vmstat`, not `wa`. A high `r` value relative to CPU count indicates CPU saturation. The `wa` column specifically measures I/O wait time.
- Why C is incorrect: Swap utilization is shown in the `si` (swap-in) and `so` (swap-out) columns. Non-zero `si`/`so` values indicate memory pressure causing swapping. The `wa` column is unrelated to swap usage levels.
- Why D is incorrect: `vmstat` does not report network interface utilization. Network statistics are viewed with tools like `ip -s link`, `sar -n DEV`, or `netstat -s`. The `wa` column is strictly a CPU metric measuring time blocked waiting on disk I/O.

### Question 5

An administrator wants to view only log messages at `err` priority and higher (critical, alert, emergency) from the current boot using `journalctl`. Which command is correct?

- A) journalctl -b -p err
- B) journalctl -b --level=error
- C) journalctl -b -t err
- D) journalctl -b -u err

Correct Answer: A) journalctl -b -p err

Distractor Analysis:

- Why B is incorrect: `--level` is not a valid `journalctl` option. The correct flag for filtering by syslog priority is `-p` (or `--priority`). This command would fail with an unrecognized option error.
- Why C is incorrect: The `-t` flag filters by syslog identifier (the program name that generated the message), not by priority level. `journalctl -b -t err` would attempt to find messages from a program named `err`, returning no results.
- Why D is incorrect: The `-u` flag filters by systemd unit name. `journalctl -b -u err` would search for a service unit named `err`, which does not exist. It is not a priority filter.

### Question 6

A logrotate configuration stanza contains `rotate 7` and `compress`. After 9 total logrotate runs, how many compressed rotated files will exist alongside the current active log file?

- A) 9 compressed files
- B) 7 compressed files
- C) 6 compressed files and 1 uncompressed rotated file
- D) 8 compressed files

Correct Answer: B) 7 compressed files

Distractor Analysis:

- Why A is incorrect: `rotate 7` instructs logrotate to keep a maximum of 7 old (rotated) copies. After the 8th rotation, the oldest file is deleted. After 9 runs, there are still only 7 old files on disk — the 8th and 9th rotation each caused the oldest file to be removed.
- Why C is incorrect: `compress` without `delaycompress` compresses each rotated file immediately. The uncompressed scenario (6 compressed + 1 uncompressed) applies only when `delaycompress` is present, which defers compression of the most-recently-rotated file by one cycle.
- Why D is incorrect: 8 old files would require `rotate 8`. With `rotate 7`, the 8th rotation deletes the oldest file, leaving 7. The count never exceeds the `rotate N` value.

### Question 7

An administrator needs to investigate why a production server was slow between 2 AM and 3 AM yesterday. The administrator was not on duty at that time. Which tool and command sequence would allow them to review CPU utilization for that specific time window?

- A) vmstat --since "yesterday 02:00" --until "yesterday 03:00"
- B) top -b -n 1 | grep "02:00"
- C) sar -u -s 02:00:00 -e 03:00:00 -f /var/log/sysstat/sa$(date -d yesterday +%d)
- D) journalctl --since "yesterday 02:00:00" --until "yesterday 03:00:00" -u cpu

Correct Answer: C) sar -u -s 02:00:00 -e 03:00:00 -f /var/log/sysstat/sa$(date -d yesterday +%d)

Distractor Analysis:

- Why A is incorrect: `vmstat` does not support `--since` or `--until` flags. It only reports current statistics at intervals. It has no historical data capability — it cannot show what happened hours or days ago.
- Why B is incorrect: `top -b -n 1` takes a single snapshot of the current system state. It cannot look back in time. The output does not contain historical timestamps that could be grepped for a past time.
- Why D is incorrect: `journalctl` shows log messages, not structured CPU performance metrics. There is no systemd unit called `cpu`. While journald does store kernel messages, it is not a substitute for sar's historical performance data collection.

### Question 8

An administrator runs `logger -p auth.warning "Test message"` and then runs `grep "Test message" /var/log/auth.log`. The message does not appear. What is the most likely explanation?

- A) logger requires root privileges and the command was run as a regular user.
- B) The `-p auth.warning` flag is invalid; logger only accepts numeric priority values.
- C) The system is running RHEL, where auth facility messages go to /var/log/secure, not /var/log/auth.log.
- D) logger sends messages to the kernel ring buffer, not to syslog.

Correct Answer: C) The system is running RHEL, where auth facility messages go to /var/log/secure, not /var/log/auth.log.

Distractor Analysis:

- Why A is incorrect: `logger` does not require root privileges. A regular user can inject messages into the syslog system using `logger`. The facility and priority flags work regardless of user privilege level.
- Why B is incorrect: `logger` accepts both named priority values (`auth.warning`) and numeric values. The `facility.priority` syntax is the standard and preferred form. There is nothing invalid about using named values.
- Why D is incorrect: `logger` uses the syslog(3) system call to deliver messages directly to the syslog daemon (rsyslog or syslog-ng), not the kernel ring buffer. The kernel ring buffer is written by the kernel itself and read with `dmesg`.

### Question 9

An administrator reviews the `free -h` output and sees: total=16G, used=14G, free=500M, buff/cache=8G, available=9G. A developer reports that the application cannot allocate more memory. How should the administrator interpret these numbers?

- A) The server is nearly out of memory. With only 500 MB free and 14 GB used, new processes will likely trigger the OOM killer.
- B) The server has approximately 9 GB available for new processes because the buff/cache memory is reclaimable by the kernel when needed.
- C) The server is critically low on memory because buff/cache of 8 GB is consuming resources that should be free.
- D) The `available` column is inaccurate and the `free` column (500 MB) should be used for capacity planning decisions.

Correct Answer: B) The server has approximately 9 GB available for new processes because the buff/cache memory is reclaimable by the kernel when needed.

Distractor Analysis:

- Why A is incorrect: The `used` column in `free` output includes buff/cache memory. The 14 GB used figure includes the 8 GB disk cache. This does not mean only 500 MB is available — the `available` column accounts for reclaimable cache and is the correct metric for capacity planning.
- Why C is incorrect: Linux deliberately uses spare RAM as disk cache to improve I/O performance. This is not memory "consumed" in a problematic sense — the kernel releases buff/cache immediately when applications need more RAM. High buff/cache is a sign of a healthy, well-utilized system.
- Why D is incorrect: The `available` column is the most accurate metric for new process memory. It is calculated by the kernel as free + reclaimable buff/cache. The `free` column (raw unused memory) significantly understates available capacity on a typical Linux system.

### Question 10

An administrator runs `iostat -x 1 3` and observes that `/dev/sda` shows `%util` of 98% and `await` of 180 ms across all three samples. What is the correct interpretation and recommended next diagnostic step?

- A) The disk is nearly saturated (98% busy) with high latency (180 ms is well above the 10-20 ms SSD threshold). Run `iotop` or `ps aux --sort=-%cpu` to identify which processes are generating the I/O.
- B) The `await` value of 180 ms is within normal range for a spinning disk. No action is required.
- C) `%util` at 98% indicates the disk has 2% free capacity remaining. The disk needs to be expanded with LVM.
- D) High `await` is always caused by insufficient RAM causing swap activity. Run `free -h` to confirm and add swap space.

Correct Answer: A) The disk is nearly saturated (98% busy) with high latency (180 ms is well above the 10-20 ms SSD threshold). Run `iotop` or `ps aux --sort=-%cpu` to identify which processes are generating the I/O.

Distractor Analysis:

- Why B is incorrect: 180 ms await is high even for a spinning HDD (acceptable range is up to ~50 ms for HDDs, 10-20 ms for SSDs). Values this high indicate severe I/O contention or a failing/degraded disk, not normal operation.
- Why C is incorrect: `%util` in iostat measures the percentage of time the device was busy processing I/O requests — it is a utilization/saturation metric, not a disk space metric. Disk space is checked with `df -h`. A `%util` of 98% means the disk was busy 98% of the time, not that it is 98% full.
- Why D is incorrect: High `await` can be caused by I/O saturation, a slow or failing disk, RAID degradation, or intensive workloads — not exclusively by swap activity. Swap-induced I/O would show up in vmstat's `si`/`so` columns and would not necessarily produce 180 ms await values. The correct tool for process-level I/O attribution is `iotop`.
