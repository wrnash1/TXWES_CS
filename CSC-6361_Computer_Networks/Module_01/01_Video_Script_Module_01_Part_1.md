### Section 2: OSPF Fundamentals Review — What You Already Know

[02:00 – 04:00]
[SHOW SLIDE: OSPF basic concepts — single area, DR/BDR election, LSA types 1 and 2]

Before we scale OSPF, let's confirm the foundation. In a single-area OSPF network:
- All routers participate in the same **area** — typically Area 0, the backbone.
- Routers exchange **Link-State Advertisements (LSAs)** to build identical copies of the **Link-State Database (LSDB)**.
- Each router independently runs the **Dijkstra SPF algorithm** on that database to calculate the shortest path to every destination.
- On a broadcast network (Ethernet), a **Designated Router (DR)** and **Backup Designated Router (BDR)** are elected to reduce the volume of LSA flooding.

This is clean and elegant for small networks. But what happens when you have 200 routers in a single OSPF area? Every router stores every LSA. Every topology change forces every router to re-run SPF. The CPU and memory burden becomes unsustainable.

The solution: **Multi-Area OSPF**.

### Section 3: Multi-Area OSPF Architecture

[04:00 – 08:30]
[SHOW DIAGRAM: Multi-area OSPF topology — Area 0 (backbone) with Area 1, Area 2 connected via ABRs. ABR routers highlighted. ASBR shown connecting to external routing domain.]

[Alt-text: A network diagram showing three OSPF areas. Area 0 (backbone) is in the center with three routers. Area 1 connects to the left via a router labeled ABR-1. Area 2 connects to the right via a router labeled ABR-2. An ASBR router in Area 2 connects to an external cloud labeled "External AS (BGP or EIGRP domain)."]

Multi-Area OSPF introduces a hierarchical routing structure. Here are the core concepts:

**Backbone Area (Area 0):**
Every OSPF multi-area design requires an Area 0 — the backbone. All non-backbone areas must connect, directly or via a virtual link, to Area 0. This is non-negotiable in OSPF design. Area 0 is the transit hub through which inter-area routing information must pass.

**Area Border Routers (ABRs):**
An ABR is a router that connects to two or more OSPF areas, with at least one interface in Area 0. ABRs are critical — they summarize routing information between areas using **Type 3 LSAs** (Summary LSAs). This summarization is what controls the size of the LSDB in each area.

**AS Boundary Routers (ASBRs):**
An ASBR redistributes external routes (from BGP, EIGRP, or static routes) into OSPF as **Type 5 External LSAs**. This is how OSPF learns about routes that originate outside the OSPF domain.

**LSA Types in Multi-Area OSPF:**

| LSA Type | Name | Flooded To |
|---|---|---|
| Type 1 | Router LSA | Within its originating area only |
| Type 2 | Network LSA | Within its originating area only |
| Type 3 | Summary LSA | Generated by ABR, flooded to other areas |
| Type 4 | ASBR Summary LSA | Tells other areas where the ASBR is |
| Type 5 | External LSA | Flooded through the entire OSPF domain |
| Type 7 | NSSA External LSA | Used in Not-So-Stubby Areas |

> **Graduate Exam Tip:** Understanding which LSA types cross area boundaries — and which do not — is one of the most commonly tested CCNP concepts. Type 1 and Type 2 never leave their originating area. Types 3, 4, and 5 can cross area boundaries (with restrictions in stub areas).

### Section 4: OSPF Stub Area Types

[08:30 – 11:00]
[SHOW TABLE: Stub area comparison — Stub, Totally Stubby, NSSA, Totally NSSA]

Multi-area OSPF gives us the ability to further reduce LSA overhead by defining **stub areas**. The concept: if a remote area has only one exit point (an ABR), why does it need to know about every external route in the OSPF domain? It does not. A stub area replaces Type 5 External LSAs with a single default route injected by the ABR.

| Stub Type | Blocks | Replaces With | Use Case |
|---|---|---|---|
| **Stub** | Type 5 LSAs (external) | Default route (Type 3) | Remote area with no ASBR, single ABR |
| **Totally Stubby** | Type 3, 4, 5 LSAs | Default route only | Remote area needing minimal routing table |
| **NSSA** | Type 5 LSAs only | Allows Type 7 (local external) | Remote area that HAS its own ASBR |
| **Totally NSSA** | Type 3, 4, 5 LSAs | Default route + Type 7 locally | Remote area with ASBR but minimal inter-area routes |

The practical impact: a Totally Stubby area router may have a routing table with only 3–5 entries — its local subnet, intra-area routes, and a single default route pointing to the ABR. This dramatically reduces CPU and memory use on remote branch routers.

### Section 5: Inter-Area Route Summarization

[11:00 – 14:00]
[SHOW DIAGRAM: ABR summarizing multiple Area 1 subnets into one summary route advertised to Area 0]

One of the most powerful tools an ABR has is **route summarization**. Without summarization, every specific subnet in Area 1 is advertised individually to Area 0 and Area 2 via Type 3 LSAs. With summarization, the ABR aggregates contiguous subnets into a single summary advertisement.

**Example:**
Area 1 contains subnets: 10.1.0.0/24, 10.1.1.0/24, 10.1.2.0/24, 10.1.3.0/24.

Without summarization: four Type 3 LSAs advertised to Area 0.
With summarization: one Type 3 LSA — **10.1.0.0/22** — advertised to Area 0.

IOS command on the ABR:
```
router ospf 1
 area 1 range 10.1.0.0 255.255.252.0
```

The benefits compound as the network grows. In a large enterprise, proper summarization is the difference between a stable, scalable OSPF domain and a CPU-thrashing topology that bogs down during every network change.
