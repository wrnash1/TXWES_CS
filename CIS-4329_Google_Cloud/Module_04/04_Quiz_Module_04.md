**Question 1**
You want to ensure that your application can survive the failure of a single Compute Engine instance. If an instance crashes or becomes unresponsive, you want Google Cloud to automatically delete the broken instance and replace it with a fresh, identical one. Which feature should you implement?

A) An Unmanaged Instance Group
B) A Managed Instance Group (MIG) with an autohealing health check
C) A Global HTTP(S) Load Balancer
D) Cloud Monitoring Alerting Policies

*   **Correct Answer:** B) A Managed Instance Group (MIG) with an autohealing health check
*   **Distractor Analysis:**
    *   *Why A is incorrect:* Unmanaged instance groups are arbitrary collections of heterogeneous VMs with no support for autoscaling, autohealing, or automatic instance replacement.
    *   *Why C is incorrect:* A load balancer distributes traffic away from unhealthy instances but does not have the authority to delete the broken VM and provision a replacement — the MIG does that via its autohealing policy.
    *   *Why D is incorrect:* Alerting policies send notifications when a condition is met but do not take any automated remediation action such as deleting and recreating a VM.

**Question 2**
Your company requires that all system and application logs generated by Compute Engine instances be retained for a minimum of 5 years to meet financial compliance regulations. Cloud Logging retains logs for 30 days by default. How should you automate long-term retention?

A) Create a Cloud Monitoring Uptime Check pointing at each log-generating VM.
B) Take daily snapshots of all Compute Engine boot disks and store them as backups.
C) Create a Log Sink to export the logs to a Cloud Storage bucket using the Archive storage class.
D) Write a startup script that emails daily log digests to the compliance team.

*   **Correct Answer:** C) Create a Log Sink to export the logs to a Cloud Storage bucket using the Archive storage class.
*   **Distractor Analysis:**
    *   *Why A is incorrect:* Uptime Checks verify that a URL or TCP port is responding — they have no connection to log retention or compliance storage.
    *   *Why B is incorrect:* Disk snapshots capture full disk state, not structured log data; this approach is impractical, unsearchable, and far more expensive than native log export for 5-year retention.
    *   *Why D is incorrect:* Emailing log digests is not a secure, searchable, or auditable compliance solution; Log Sinks natively automate continuous log routing to durable, cheap storage.

**Question 3**
A Cloud Storage bucket contains project assets that are actively used during a project lifecycle. After the project closes, the objects must be retained for 90 days before being permanently deleted. Which Cloud Storage feature implements this automatically without manual intervention?

A) Enable Object Versioning on the bucket and manually delete old versions after 90 days.
B) Configure a Lifecycle Policy with a `Delete` action and an `age` condition of 90 days.
C) Change the bucket's default storage class to Archive after the project closes.
D) Use `gsutil rm -r gs://bucket-name` in a scheduled cron job 90 days after project close.

*   **Correct Answer:** B) Configure a Lifecycle Policy with a `Delete` action and an `age` condition of 90 days.
*   **Distractor Analysis:**
    *   *Why A is incorrect:* Object Versioning preserves old copies of objects but requires manual deletion; it does not automatically delete objects after a set time period.
    *   *Why C is incorrect:* Changing the storage class changes the cost tier but does not delete objects after 90 days; the data persists indefinitely at the Archive cost.
    *   *Why D is incorrect:* A cron job is a fragile, manual approach that can fail silently; Lifecycle Policies are the native, managed, zero-maintenance solution for automated object deletion.

**Question 4**
You need to share a private file stored in a Cloud Storage bucket with an external business partner who does not have a Google Account. The access should expire after 24 hours. What is the correct approach?

A) Temporarily make the bucket public by setting its IAM policy to `allUsers` with `roles/storage.objectViewer`.
B) Create a Google Account for the partner and grant them `roles/storage.objectViewer` on the bucket.
C) Generate a Signed URL for the specific object with a 24-hour expiration and send it to the partner.
D) Copy the file to a second bucket with public access enabled, then delete it after 24 hours.

*   **Correct Answer:** C) Generate a Signed URL for the specific object with a 24-hour expiration and send it to the partner.
*   **Distractor Analysis:**
    *   *Why A is incorrect:* Making the bucket public exposes all objects in it to anyone on the internet — not just the partner — and requires manual reversal after 24 hours, introducing security risk.
    *   *Why B is incorrect:* Creating a Google Account for every external partner is operationally unsustainable and gives the partner a persistent GCP identity rather than a time-limited access token.
    *   *Why D is incorrect:* Copying to a public bucket exposes all objects in that bucket and relies on manual cleanup after 24 hours; Signed URLs are the purpose-built, self-expiring mechanism for this use case.

**Question 5**
Your organization stores financial audit logs in a Cloud Storage bucket. Regulations require that audit logs cannot be deleted or overwritten for at least 7 years after creation. Which Cloud Storage feature enforces this immutability requirement?

A) Enable Object Versioning so previous versions are always recoverable.
B) Apply a Retention Policy with a 7-year retention period to the bucket.
C) Set a lifecycle policy to transition objects to Archive storage after 1 year.
D) Grant only `roles/storage.objectViewer` to all users so no one can delete objects.

*   **Correct Answer:** B) Apply a Retention Policy with a 7-year retention period to the bucket.
*   **Distractor Analysis:**
    *   *Why A is incorrect:* Object Versioning preserves overwritten or deleted objects as noncurrent versions, but an administrator with sufficient permissions can still permanently delete all versions; it does not enforce legal hold-style immutability.
    *   *Why C is incorrect:* Transitioning objects to Archive storage changes the cost tier but does not prevent deletion by authorized principals; retention requires a Retention Policy, not a storage class change.
    *   *Why D is incorrect:* An IAM Viewer role prevents most users from deleting objects, but project owners and Storage Admins can still override it; a Retention Policy creates a hard lock that even admins cannot circumvent before the retention period expires.
