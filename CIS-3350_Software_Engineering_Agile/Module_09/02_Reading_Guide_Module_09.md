# Reading Guide: Module 09 – Kanban and Lean Principles

## Course: CIS-3350_Software_Engineering_Agile (Professional Scrum Master (PSM I))

---

### Introduction

Welcome to **Module 09 – Kanban and Lean Principles**! Kanban and Lean are the most important Agile-adjacent frameworks to understand for the PSM I, because questions frequently test whether students can distinguish between Scrum's prescribed structure and Kanban's flow-based approach — and whether they understand which Lean principles Scrum draws upon.

This module covers the core mechanics of Kanban (visual board, WIP limits, flow metrics) and the Lean thinking concepts that underpin both Kanban and Scrum (waste elimination, pull systems, continuous improvement). The PSM I also tests knowledge of Scrumban — a hybrid approach — and when each method is most appropriate.

---

### 1. High-Yield Glossary

Review these essential definitions carefully. The certification exam expects you to know these concepts inside and out:

* **Kanban:** A method for managing knowledge work that emphasizes visualizing the workflow on a board, limiting work in progress (WIP), managing flow, making process policies explicit, and continuously improving. Unlike Scrum, Kanban has no prescribed roles, timeboxed iterations, or mandatory ceremonies — work flows continuously as capacity becomes available.

* **WIP limit (Work In Progress limit):** A constraint placed on the number of work items allowed in any given column of a Kanban board at one time. WIP limits force the team to finish existing work before starting new work, reducing multitasking, exposing bottlenecks, and improving flow efficiency.

* **Lean thinking:** A philosophy originating in the Toyota Production System that focuses on delivering maximum customer value while eliminating waste (muda). The seven wastes of software development (adapted from Lean manufacturing) include partially done work, extra features, relearning, handoffs, task switching, delays, and defects.

* **Pull system:** A workflow principle in which new work is pulled into active development only when capacity exists, rather than being pushed in regardless of team load. Both Kanban's WIP limits and Scrum's Sprint commitments implement pull — work is not started until the team can handle it.

* **Cycle time:** The elapsed time from when a work item starts active development to when it is delivered. Reducing cycle time is a primary flow metric in Kanban. Shorter cycle times mean faster delivery of value to customers and faster feedback loops.

### 2. Certification Exam Tips

* **PSM I Focus — Scrum vs. Kanban:** Scrum prescribes roles, events, artifacts, and timeboxed Sprints. Kanban prescribes none of these — it only requires visualization, WIP limits, and flow management. PSM I questions that describe a team with no Sprints, no defined roles, and no Sprint events are describing Kanban, not Scrum.
* **Scenario Trap — Scrumban:** Some PSM I questions describe teams combining elements of both frameworks. The key principle: if a team claims to do Scrum, they must follow all Scrum events and accountabilities as defined in the Scrum Guide. Selectively removing parts of Scrum (e.g., skipping the Sprint Retrospective) is not Scrum.
* **Lean waste in software:** The PSM I expects familiarity with the concept of waste elimination even if not the full seven wastes list. "Partially done work" — work that is started but not delivered — is the most commonly tested Lean waste concept.
* **Kanban does not have a "backlog" in the Scrum sense:** Kanban uses an input queue, but it does not have a Product Owner, a Sprint, or a Sprint Backlog. Questions that mix Kanban terminology with Scrum terminology are often testing whether you recognize the distinction.
* **Study Resource:** [The Official Kanban Guide](https://kanbanguides.org/) is a free document analogous to the Scrum Guide for Kanban. Read the first two sections for PSM I preparation. The [Lean Enterprise Institute's Lean Thinking introduction](https://www.lean.org/explore-lean/what-is-lean/) provides Lean background.

### Lab & Command Integration

In this week's hands-on lab, you will:

* **Build and analyze a Kanban board:** Given a set of 12 work items in various states, construct a five-column Kanban board (Backlog, Analysis, Development, Testing, Done), apply WIP limits to each active column, and identify any current bottlenecks.
* **Calculate cycle time:** Using a provided dataset of five completed work items with start and completion dates, calculate the cycle time for each item and the average cycle time for the set.
* **Identify Lean waste:** Review three provided workflow scenarios and categorize the primary type of Lean waste present in each (e.g., partially done work, task switching, handoff delays), explaining how a WIP limit or Kanban practice would address it.
