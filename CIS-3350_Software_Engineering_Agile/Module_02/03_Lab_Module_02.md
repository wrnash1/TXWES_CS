## Overview

This lab is an analysis and reflection exercise. You will analyze real team behavior scenarios against the Agile Manifesto values and principles, write principle-to-practice mappings, and evaluate a hypothetical team's Agile maturity. No programming is required.

The ability to identify Manifesto alignment or misalignment in a narrative scenario is a direct PSM I exam skill.

Estimated time: 90–120 minutes

## Part 1 — Manifesto Value Analysis (30 points)

### Part 1 Instructions

Each of the six team behaviors below either upholds or violates one or more Agile Manifesto values. For each behavior:

1. Identify which of the four Manifesto values is most relevant (name it verbatim)
2. State whether the behavior upholds or violates the value
3. Write 2–3 sentences explaining your reasoning with specific reference to the value's meaning

### Behaviors

Behavior A: A project manager insists that all team communication go through a formal change request system, even for small questions between developers and the Product Owner.

Behavior B: The team ships a tested, working user login feature at the end of every two-week Sprint, even when stakeholders ask for a longer first Sprint to "get more done."

Behavior C: The contract between a vendor and client specifies a fixed list of 200 features. When the client discovers mid-project that 40 of those features are not actually needed, the vendor refuses to re-prioritize because the contract is binding.

Behavior D: The team discovers in Sprint 8 that a core architectural decision made in Sprint 2 was wrong. The Scrum Master facilitates a conversation and the team replans to address the technical debt, even though it delays a planned feature.

Behavior E: The team produces a 300-page functional specification document before writing any code, and the document is reviewed and approved by all stakeholders before development begins.

Behavior F: The team is consistently working 60-hour weeks to meet release commitments. The Scrum Master does not raise this issue because "the team is highly motivated and doesn't mind."

### Grading (30 points)

- 5 points per behavior: correct value identification (2 pts), correct upholds/violates judgment (1 pt), quality of explanation (2 pts)

## Part 3 — Team Agile Maturity Assessment (35 points)

### Part 3 Instructions

Read the following team profile and complete the assessment tasks that follow.

### Team Profile: Alpha Squad at FinTech Startup

Alpha Squad is a 7-person development team at a financial technology startup. They have been "doing Agile" for six months. Here is what their process looks like:

- They run two-week Sprints
- The project manager writes all the user stories and assigns them to individual developers before Sprint Planning
- Sprint Planning lasts four hours, during which the project manager walks through the stories one by one; developers estimate but do not modify the stories
- The Daily Scrum is a 30-minute status meeting where each developer reports to the project manager: "Yesterday I did X, today I'll do Y, blockers: none"
- At the end of each Sprint, the project manager reviews the code and decides if it meets requirements; stakeholders are not invited
- There is no Sprint Retrospective — the project manager says "we don't have time for that"
- The team consistently delivers only 60% of what was committed in Sprint Planning

### Assessment Tasks

Task 1 — Manifesto Analysis (200–250 words): Identify three specific Manifesto values or principles that Alpha Squad is violating. For each violation, describe the specific behavior that constitutes the violation and what the team should do differently.

Task 2 — Root Cause (100–150 words): In your view, what is the single most damaging practice in this team's approach, and why? What one change would have the greatest positive impact on both Manifesto alignment and delivery outcomes?

Task 3 — Improvement Plan (numbered list): Write a prioritized list of five specific, actionable changes Alpha Squad should make to better align with the Agile Manifesto. Order them from most impactful to least impactful, with a one-sentence justification for each.

### Part 3 Grading (35 points)

- Task 1 — Manifesto Analysis: 15 points (5 pts per violation: identification 2, behavior description 2, recommendation 1)
- Task 2 — Root Cause: 10 points (identification 4, explanation 4, reasoning quality 2)
- Task 3 — Improvement Plan: 10 points (5 actionable items 6 pts, prioritization logic 2, justification quality 2)

## Part 9 — Challenge Exercise

### Challenge 1: Manifesto Stress Test — Edge Cases

The Agile Manifesto was written with collaborative, creative software development in mind. Apply it to three edge-case scenarios where the values create tension or ambiguity:

1. Select any two of the four Manifesto values. Construct a realistic project scenario where honoring one value fully would make it harder to honor the other. Write two to three sentences describing the tension.
2. For each tension you identified, describe what a senior Agile practitioner would actually do in practice — not which value "wins," but how they would balance the two.
3. Identify one of the twelve principles that most directly helps resolve each tension and explain why.

### Challenge 2: Rewrite Alpha Squad's Process

Using the Alpha Squad profile from Part 3, rewrite their development process as a set of six bullet points that fully align with the Agile Manifesto values and principles. Each bullet must:

1. Directly replace one of Alpha Squad's current dysfunctional practices.
2. Name the specific value or principle it addresses.
3. Be specific enough that Alpha Squad could actually implement it next Sprint (not generic advice like "be more Agile").
4. Conclude with a one-paragraph prediction: if Alpha Squad implemented all six changes simultaneously, which metric (Sprint Goal achievement rate, team morale, stakeholder trust) would improve first and why?

### Reflection Questions

1. The Manifesto says "we value the items on the left more" — but in your own project or team experience (or a hypothetical), can you identify a situation where the right-side items (documentation, processes, contracts, plans) were genuinely the more important priority? What does that tell you about the limits of any set of values?
2. Principle 5 says to "build projects around motivated individuals." What specific things can a Scrum Master or manager do to create and maintain the environment and support that principle calls for?
