## 2. Course Description

CIS-4355 provides a comprehensive survey of Internet of Things (IoT) and embedded systems security principles aligned with current industry certification frameworks. Topics include IoT architecture layers, microcontroller hardware and programming, wireless and wired IoT communication protocols, cloud IoT platform security, sensor integration, edge computing, the OWASP IoT Top 10 threat model, firmware security and secure boot, device lifecycle management, time-series data pipelines, machine learning at the edge, industrial IoT and SCADA systems, and regulatory compliance standards. Students complete weekly hands-on lab activities that reinforce each module's concepts using real tools and simulated environments. The course culminates in a capstone threat modeling exercise and a final exam aligned with the IoT & Embedded Security (General Principles) certification blueprint.

Prerequisite knowledge: CIS-2310 or equivalent networking fundamentals; basic familiarity with Linux command line and a scripting language (Python preferred).

## 3. Zero Textbook Cost (ZTC) Materials

This course is designated **Zero Textbook Cost**. All required learning materials are freely available online and embedded in the Canvas LMS course shell. Students pay no textbook fees.

### Primary OER Resources

*   **Primary Open Reference:** [OWASP IoT Security Project Guides & Embedded Systems Wiki](https://owasp.org/www-project-internet-of-things/) — the OWASP IoT Top 10 and associated guidance documents serve as the primary security framework reference throughout the course.
*   **Primary Video Lecture Series:** [IoT Course & Embedded Systems Tutorials by freeCodeCamp](https://www.youtube.com/watch?v=h0J8f60LdB0) — a 7-hour open-access video course covering IoT hardware, protocols, cloud integration, and security concepts aligned with the course curriculum.
*   **Supplementary Reference:** Vendor documentation for AWS IoT Core, Azure IoT Hub, TensorFlow Lite, and InfluxDB is freely accessible at their respective developer portals and is linked within individual module reading guides.

### Optional Hardware (Not Required)

Students may optionally use physical hardware to complete lab activities at a deeper level. All labs are designed to be completable in software simulation without hardware. Optional hardware that enhances the lab experience:
*   Raspberry Pi 4 or 5 (Model B, 4 GB RAM recommended) — for edge gateway and inference labs
*   Arduino Uno or Arduino Nano 33 IoT — for sensor interfacing and GPIO labs
*   DHT22 or BME280 temperature/humidity sensor — for sensor integration labs
*   USB-to-UART adapter — for UART serial communication labs

None of the above are required for grading. All labs include a software-simulation alternative path.

## 6. Lab Assignment Guidelines

*   Labs are submitted as a written lab report documenting commands executed, outputs observed, and a brief analysis section answering the lab's reflection questions.
*   Lab reports must include: (1) a header identifying the module number, lab title, student name, and date; (2) screenshots or command outputs with annotations; (3) answers to reflection questions in complete sentences.
*   Minimum length: 300 words of analysis (excluding screenshots and command output).
*   File format: PDF preferred; DOCX accepted. Canvas submission only — email submissions are not accepted.

---

## 7. Discussion Board Guidelines

*   Each module's discussion board has a specific prompt aligned with the module's security topics.
*   Initial post requirements: minimum 150 words, must reference at least one concept from the module's reading guide glossary, must be submitted by Thursday 11:59 PM Central of the module week.
*   Peer response requirements: two responses to classmates, minimum 75 words each, must substantively engage with the peer's argument (not just "I agree"), due Sunday 11:59 PM Central.

## 8. Academic Integrity

All submitted work must be the student's own. Prohibited: copying quiz answers from other students, submitting lab reports generated entirely by AI without original analysis, plagiarizing text from online sources. Permitted: using AI tools (ChatGPT, Claude, Copilot) as a reference and learning aid, provided that any AI-assisted content is disclosed and the analysis sections of lab reports represent the student's own reasoning and observations. Violations are reported to the Texas Wesleyan Dean of Students under the Academic Dishonesty policy.
