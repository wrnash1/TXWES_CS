## Scenario A: The Deleted State File

A startup is building its first Terraform-managed cloud environment. The team stores the state file locally in the project repository. A developer runs `git clean -fd` to clean up untracked files before a presentation and inadvertently deletes `terraform.tfstate`. The team now has a running production environment — an EC2 instance, an RDS database, and a VPC — but Terraform no longer knows any of these resources exist.

For your initial post (175–225 words), address all three of the following points:

1. Explain the immediate consequence of the missing state file when the team runs `terraform plan` the next day.
2. Describe the step-by-step process to recover. Identify the specific Terraform command used to bring each existing resource back under management, and explain what must be prepared before each import command can run.
3. Explain what the team should have done from the beginning to prevent this situation. Reference the specific remote backend features that would have made this incident impossible.

## Scenario B: The Concurrent Apply Problem

A DevOps team of four engineers manages cloud infrastructure with Terraform. They use an S3 remote backend but neglected to configure DynamoDB locking when they set it up six months ago. Recently, two engineers ran `terraform apply` simultaneously from their laptops — one deploying a security group change and the other adding a new EC2 instance. The next morning, the team notices that the state file reflects only one of the two changes, and the infrastructure does not match the configuration.

For your initial post (175–225 words), address all three of the following points:

1. Explain exactly why this happened. Describe the race condition at the state file level, including the role of the `serial` field in state.
2. Describe how DynamoDB locking prevents this problem. Explain what happens at each step when two applies attempt to run simultaneously with locking enabled.
3. Propose a process-level safeguard, beyond enabling locking, that would prevent engineers from running ad-hoc `terraform apply` commands directly from their laptops. Reference a Terraform tooling approach.

## Scenario C: The State Security Audit

A security team is performing an audit of a company's cloud automation practices. They discover that Terraform state files are stored in a public S3 bucket without encryption, and that the state files contain plaintext database passwords, RDS connection strings, and a private TLS key generated by Terraform for an API gateway. The files are also checked into a Git repository.

For your initial post (175–225 words), address all three of the following points:

1. Identify each specific security vulnerability in this scenario and explain the risk each poses. Reference the Terraform state security properties from the reading guide.
2. Explain why `sensitive = true` on a Terraform variable or output does not solve the state security problem. Be specific about what `sensitive = true` does and does not do.
3. Describe a complete remediation plan. Address the S3 bucket configuration, Git history, and future state management practices. Your plan should not require starting from scratch.
