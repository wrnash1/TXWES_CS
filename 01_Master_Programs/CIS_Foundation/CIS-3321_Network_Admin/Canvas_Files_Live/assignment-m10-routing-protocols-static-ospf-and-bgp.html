Lab Activity: Module 10 — Routing Protocols: Static, OSPF, and BGP

CIS-3321 Network Administration | CompTIA Network+ (N10-009)

Texas Wesleyan University | Professor Nash

Overview

This lab has two parts. Part 1 uses Cisco Packet Tracer to configure static routes and single-area OSPF between three routers and verify connectivity and administrative distance behavior. Part 2 is a paper-based BGP path-selection exercise, since a realistic multi-AS BGP topology exceeds what a single Packet Tracer lab can meaningfully simulate — you will analyze a provided routing table and path-attribute data to determine BGP's actual path selection.

Estimated Time: 70–85 minutes

Required Tools:

  • Cisco Packet Tracer 8.x (free download at netacad.com with a free account)

Learning Objectives

By the end of this lab, you will be able to:

  1. Configure static routes, including a default route, on a Cisco router.
  2. Configure single-area OSPF on multiple routers and verify neighbor adjacency.
  3. Interpret show ip route output to identify route sources and administrative distance in action.
  4. Explain why a static route is preferred over an OSPF-learned route to the same destination.
  5. Apply BGP path-selection rules (AS-Path length, Local Preference) to determine the best path in a given scenario.

Part 1: Static Routing and OSPF in Packet Tracer

Part 1 Step 1: Build the Topology

Open Packet Tracer and create the following topology:

  • R1 (LAN: 192.168.1.0/24) — connected to R2 via a serial or Ethernet WAN link (10.0.12.0/30)
  • R2 — connected to R3 via a WAN link (10.0.23.0/30)
  • R3 (LAN: 192.168.3.0/24)

Assign IP addresses to all interfaces per the addressing scheme above and bring all interfaces up (no shutdown).

Part 1 Step 2: Configure Static Routes

On R1, configure a static route to reach R3's LAN (192.168.3.0/24) via R2:

R1(config)# ip route 192.168.3.0 255.255.255.0 10.0.12.2

On R3, configure a static route to reach R1's LAN (192.168.1.0/24) via R2:

R3(config)# ip route 192.168.1.0 255.255.255.0 10.0.23.1

On R2, no static routes are needed if R2 has directly connected interfaces to both WAN links — R2 already knows both.

Verify with show ip route on R1 and R3. Confirm the routes appear with an S code (static). Test connectivity with ping 192.168.3.1 from a PC on R1's LAN to a PC on R3's LAN.

Part 1 Step 3: Convert to OSPF

Remove the static routes you configured in Step 2 (no ip route ...), then configure single-area OSPF (Area 0) on all three routers, advertising all connected networks:

R1(config)# router ospf 1
R1(config-router)# network 192.168.1.0 0.0.0.255 area 0
R1(config-router)# network 10.0.12.0 0.0.0.3 area 0

Configure equivalent OSPF network statements on R2 (both WAN links) and R3 (its LAN and WAN link).

Verify with show ip ospf neighbor on each router to confirm full adjacency, and show ip route to confirm routes now appear with an O code (OSPF) instead of S.

Re-test connectivity with ping 192.168.3.1 from R1's LAN.

Part 1 Step 4: Administrative Distance Conflict

With OSPF still running, re-add the original static route on R1 from Step 2:

R1(config)# ip route 192.168.3.0 255.255.255.0 10.0.12.2

Run show ip route 192.168.3.0 on R1 again.

Part 1 Analysis Questions

  1. After Step 4, which route (static or OSPF) appears as the active route in R1's routing table for 192.168.3.0/24, and what administrative distance value explains this outcome?

  2. Both the static route and the OSPF route in this topology have the exact same next hop and lead to the same destination. In a more complex topology where OSPF had discovered a better (lower-cost, more direct) path than the static route, would OSPF's better path be used? Explain why or why not, referencing AD specifically.

  3. If R2 completely failed (powered off) while only the static routes from Step 2 were configured, would R1 automatically detect the failure and find an alternate path? Would the same be true if OSPF were configured instead (assuming no alternate physical path exists)? Explain the real difference in behavior between static and dynamic routing here, even in a topology with no redundant path.

  4. show ip ospf neighbor showed a "FULL" state once adjacency completed. Name one reason two directly connected OSPF routers might fail to reach FULL state (e.g., a specific configuration mismatch).

Part 1 Deliverable

Screenshots of: the topology, show ip route output after Step 2 (static), show ip ospf neighbor and show ip route output after Step 3 (OSPF), show ip route 192.168.3.0 output after Step 4 (AD conflict), and both successful ping tests. Written answers to all four analysis questions.

Part 2: BGP Path Selection Analysis (Paper Exercise)

Part 2 Background

Your organization (AS 65001) is multihomed to two ISPs and receives the following two paths to reach the destination network 203.0.113.0/24 from its BGP table:

Path Next Hop AS-Path Local Preference Learned From
Path A ISP-1 router 65010 65020 65030 100 eBGP (ISP-1)
Path B ISP-2 router 65040 65030 150 eBGP (ISP-2)

BGP's best-path selection process evaluates attributes in a defined order; for this exercise, apply only Local Preference first (higher value preferred), and AS-Path length second (shorter path preferred) if Local Preference is equal.

Part 2 Questions

  1. Which path (A or B) will this organization's router select as the best path to 203.0.113.0/24? Show your reasoning by applying Local Preference first.

  2. If both paths had the identical Local Preference of 100, which path would be selected instead, and why? Show the AS-Path length comparison explicitly.

  3. Local Preference is only exchanged via iBGP within an autonomous system — it is never advertised to an external AS via eBGP. Given this, explain why Local Preference is described as a way for an organization to control its own outbound traffic, but not something it can use to influence how other autonomous systems route traffic toward it.

  4. Suppose your organization wants to make ISP-2 the preferred outbound path for cost reasons (ISP-2 has a cheaper contract), regardless of AS-Path length. Which BGP attribute from this exercise would you adjust, and on which routers would you configure it?

Part 2 Deliverable

Written answers to all four questions, including the explicit attribute comparisons for Questions 1 and 2.
