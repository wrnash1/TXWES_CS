## Question 1

What wildcard mask corresponds to a subnet mask of 255.255.255.252?

- A) 0.0.0.3
- B) 0.0.0.255
- C) 255.255.255.255
- D) 0.0.0.7

**Correct Answer:** A

**Distractor Analysis:**

- A is correct: Wildcard masks are calculated by subtracting the subnet mask from 255.255.255.255. 255.255.255.255 minus 255.255.255.252 equals 0.0.0.3. This is the wildcard for a /30 network.
- B is incorrect: 0.0.0.255 is the wildcard for a /24 (255.255.255.0) network, not a /30.
- C is incorrect: 255.255.255.255 is itself a subnet mask (/32 host route), not a wildcard mask. It would also be the result of subtracting 0.0.0.0 from 255.255.255.255, which is meaningless in this context.
- D is incorrect: 0.0.0.7 is the wildcard for a /29 (255.255.255.248) network.

## Question 2

Which of the following most accurately describes a Link-State Advertisement (LSA) in OSPF?

- A) A packet generated by each OSPF router describing its connected links, costs, and neighbor relationships, flooded throughout the area so all routers can build an identical Link-State Database
- B) A Hello packet sent every 10 seconds on broadcast networks to discover neighbors and maintain adjacency by confirming the neighbor is still reachable before the dead interval expires
- C) A routing update sent by a distance-vector protocol containing the full routing table, periodically broadcast to all directly connected neighbors
- D) A table stored in the router listing destination networks, next-hop IP addresses, and administrative distances computed by the routing protocol

**Correct Answer:** A

**Distractor Analysis:**

- A is correct: LSAs are the core mechanism by which OSPF routers share topology information. All routers in the same area collect LSAs to build an identical LSDB, then independently run Dijkstra's SPF algorithm to compute best paths.
- B is incorrect: This describes an OSPF Hello packet, which is a separate packet type used for neighbor discovery and adjacency maintenance — not an LSA.
- C is incorrect: This describes a distance-vector routing update (such as RIP), not an OSPF LSA. OSPF is a link-state protocol, not distance-vector.
- D is incorrect: This describes a routing table (RIB), which is the output of the SPF computation based on LSA inputs — not the LSA itself.

## Question 3

An OSPF router's Router ID selection priority is: (1) manually configured, then (2) highest loopback IP, then (3) highest physical interface IP. A router has no manually configured Router ID, no loopback interfaces, and three physical interfaces: Gi0/0 (192.168.1.1), Gi0/1 (10.0.0.1), and Gi0/2 (172.16.0.1). What Router ID will OSPF use?

- A) 192.168.1.1
- B) 10.0.0.1
- C) 172.16.0.1
- D) 0.0.0.0

**Correct Answer:** A

**Distractor Analysis:**

- A is correct: With no manual Router ID and no loopbacks, OSPF uses the highest IP address among all active physical interfaces. 192.168.1.1 is the numerically highest of the three addresses (192 > 172 > 10 in the first octet).
- B is incorrect: 10.0.0.1 is the lowest of the three IP addresses. OSPF selects the highest, not the lowest.
- C is incorrect: 172.16.0.1 is higher than 10.0.0.1 but lower than 192.168.1.1. It would not be selected when a higher IP is available.
- D is incorrect: OSPF will not use 0.0.0.0 as a Router ID. If no valid IP address exists on any active interface, OSPF cannot start.

## Question 4

An engineer configures OSPF on two directly connected routers. `show ip ospf neighbor` on both routers shows no output after two minutes. Both interfaces are up/up. Which of the following is the most likely cause?

- A) The OSPF process IDs do not match between the two routers
- B) One router's interface has a different subnet mask than the other, causing OSPF to reject the neighbor
- C) Both routers are configured as passive-interface on their LAN ports, not the WAN port
- D) The Router IDs on both routers are identical, causing a conflict

**Correct Answer:** B

**Distractor Analysis:**

- A is incorrect: OSPF process IDs are locally significant. They do not need to match between routers, and a mismatch does not prevent neighbor formation.
- B is correct: OSPF validates that both ends of a link use the same subnet. If the subnet masks differ (for example, one end uses /30 and the other uses /24), OSPF treats them as different subnets and will not form a neighbor relationship.
- C is incorrect: Passive interfaces prevent hellos on LAN ports, but the question says both interfaces are up/up and the failure is on a direct connection — the relevant question is whether the connecting interfaces (not LAN ports) are passive.
- D is incorrect: OSPF does detect duplicate Router IDs and can cause instability, but it does not prevent neighbors from forming entirely. A duplicate RID causes unpredictable behavior but is not the most likely cause of zero neighbors.

## Question 5

On a broadcast multi-access network (Ethernet), which OSPF neighbor state do two DROther routers reach with each other?

- A) Full
- B) Loading
- C) 2-Way
- D) Init

**Correct Answer:** C

**Distractor Analysis:**

- A is incorrect: Full state is reached only between a router and the DR, or between a router and the BDR, on a broadcast segment. DROthers do not form Full adjacency with each other.
- B is incorrect: Loading is a transient state during database exchange. DROthers do not remain in Loading — they proceed to 2-Way and stop there.
- C is correct: On a broadcast segment, DROther routers (those that are neither DR nor BDR) form 2-Way adjacency with each other. This means they see each other in Hello packets but do not exchange full Link-State Databases. This is expected behavior and not a failure condition.
- D is incorrect: Init is an early neighbor state where one router has seen the other's Hello but the reverse has not yet been confirmed. It is a transient state, not the stable endpoint for DROther relationships.

## Question 6

An engineer needs to trace the Layer 3 hop-by-hop path through an OSPF network to verify that routing is working correctly. Which command is most appropriate?

- A) `ping`
- B) `traceroute`
- C) `netstat -ano`
- D) `nslookup`

**Correct Answer:** B

**Distractor Analysis:**

- A is incorrect: `ping` tests end-to-end reachability but does not reveal which routers are handling the traffic or which OSPF-learned path is being used.
- B is correct: `traceroute` reveals each Layer 3 hop along the path by sending packets with incrementing TTL values. In an OSPF network, it confirms that traffic is following the OSPF-computed best path through the correct routers.
- C is incorrect: `netstat -ano` lists active TCP/UDP connections and listening ports on a local host. It provides no information about routing paths.
- D is incorrect: `nslookup` resolves DNS hostnames to IP addresses. It does not test or display routing path information.

## Question 7

An engineer configures `passive-interface GigabitEthernet0/1` under the OSPF process on R1. What is the effect?

- A) R1 stops advertising the 192.168.1.0/24 subnet connected to Gi0/1 via OSPF
- B) R1 continues to advertise the Gi0/1 subnet via OSPF but stops sending and receiving OSPF Hello packets on that interface
- C) R1 removes the Gi0/1 subnet from its routing table
- D) R1 sends OSPF Hello packets on Gi0/1 but ignores any Hellos received from neighbors on that interface

**Correct Answer:** B

**Distractor Analysis:**

- A is incorrect: Passive interface does not stop OSPF from advertising the connected subnet. The subnet is still announced to neighbors through other OSPF-active interfaces.
- B is correct: A passive interface suppresses OSPF Hello transmission and reception on that specific interface. The connected subnet continues to be included in OSPF and advertised to neighbors. This is the standard configuration for LAN segments facing end devices with no OSPF neighbors.
- C is incorrect: Passive interface has no effect on the local routing table. The connected route remains in the table.
- D is incorrect: Passive interface stops both sending and receiving OSPF Hellos on the interface — not just one direction.

## Question 8

A network administrator wants to prevent attackers from capturing plaintext management passwords on an OSPF router. Which configuration directly addresses this threat?

- A) Configure SSH for terminal access and HTTPS for web management, disabling Telnet and HTTP
- B) Configure OSPF MD5 authentication on all OSPF-enabled interfaces
- C) Enable passive-interface on all interfaces to prevent OSPF Hello exposure
- D) Use `service password-encryption` to protect passwords in the configuration file

**Correct Answer:** A

**Distractor Analysis:**

- A is correct: SSH and HTTPS encrypt management session credentials in transit, directly preventing credential capture by packet sniffers. Configure with `transport input ssh` on VTY lines.
- B is incorrect: OSPF MD5 authentication protects the routing protocol from rogue router injection — it authenticates OSPF neighbor relationships. It does not encrypt interactive management sessions or protect admin credentials.
- C is incorrect: Passive interfaces control OSPF Hello behavior on stub segments. They have no effect on management session security.
- D is incorrect: `service password-encryption` applies a weak reversible cipher to passwords stored in the running-config. It does not encrypt credentials transmitted over the network during a Telnet or HTTP session.

## Question 9

Which command on a Cisco router shows the OSPF Router ID, the number of areas, and the configured network statements?

- A) `show ip ospf neighbor`
- B) `show ip ospf interface brief`
- C) `show ip protocols`
- D) `show ip route ospf`

**Correct Answer:** C

**Distractor Analysis:**

- A is incorrect: `show ip ospf neighbor` displays the neighbor table — Router IDs of neighbors, their state, and the interface through which they are reachable. It does not show the local router's OSPF process configuration.
- B is incorrect: `show ip ospf interface brief` shows which interfaces have OSPF enabled, the area they are in, the process ID, and the interface cost. It does not show network statements or the overall process summary.
- C is correct: `show ip protocols` shows the routing protocol summary including the OSPF process ID, Router ID, networks being advertised, the area each network is in, and the administrative distance. It is the go-to command for a quick overview of OSPF configuration.
- D is incorrect: `show ip route ospf` filters the routing table to show only OSPF-learned routes. It shows destinations with OSPF administrative distance (110) but not the protocol configuration or Router ID.

## Question 10

An engineer runs `show ip ospf neighbor` and sees the neighbor in Exstart state for an extended period. Which of the following is the most likely cause?

- A) The OSPF area IDs do not match between the two routers
- B) The MTU sizes on the connecting interfaces are different between the two routers
- C) The Hello and Dead timers are mismatched
- D) The OSPF process IDs are different on the two routers

**Correct Answer:** B

**Distractor Analysis:**

- A is incorrect: A mismatched area ID prevents neighbors from progressing past the 2-Way state. It would not cause a router to be stuck in Exstart.
- B is correct: The Exstart and Exchange states involve the exchange of Database Description (DBD) packets. If MTU sizes differ between two routers, DBD packets from the higher-MTU side may be larger than the lower-MTU side accepts, causing the exchange to stall. The `ip ospf mtu-ignore` command suppresses this check.
- C is incorrect: Mismatched Hello and Dead timers prevent OSPF neighbors from forming at all — they do not progress past the Init or 2-Way state. They would not cause Exstart stalling.
- D is incorrect: OSPF process IDs are locally significant and do not need to match. A mismatch has no effect on neighbor formation.
