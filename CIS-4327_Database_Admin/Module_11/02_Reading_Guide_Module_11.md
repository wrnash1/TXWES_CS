### 1. High-Yield Glossary
Review these essential definitions carefully. The certification exam expects you to know these concepts inside and out:

*   **Query Execution Plan**: A step-by-step description of how the database engine will execute a query, generated by running `EXPLAIN` or `EXPLAIN ANALYZE` (PostgreSQL/MySQL). The plan shows whether the engine uses index scans or sequential scans, how many rows it expects to process at each step, and the estimated cost. Reading execution plans is the primary diagnostic skill for query performance tuning.
*   **Sequential Scan vs. Index Scan**: A sequential scan reads every row in a table regardless of filtering conditions (O(n) cost). An index scan uses a B-tree or hash index to directly locate matching rows (O(log n) cost). A slow query that is performing a sequential scan on a large table almost always benefits from adding an index on the filter columns.
*   **Query Insights for Cloud SQL**: A GCP-native tool that continuously samples database queries, identifies the top resource-consuming statements, visualizes query load over time, and provides execution plans and latency percentiles. It is available in the Cloud SQL console and is the recommended first tool for diagnosing slow Cloud SQL queries without modifying application code.
*   **Connection Pool Exhaustion**: A condition where all available database connections in the pool are in use and new connection requests must wait or time out. Cloud SQL supports a maximum number of connections determined by the instance's machine type and RAM. pgBouncer (for PostgreSQL) or Cloud SQL Proxy's built-in pooling are the recommended solutions for high-concurrency applications.
*   **N+1 Query Problem**: A common application-level performance anti-pattern where code executes one query to retrieve N records and then executes N additional queries to fetch related data for each record (total = N+1 queries). The fix is to use a single JOIN query or an ORM `eager loading` directive to retrieve all data in one round trip.

### 2. Certification Exam Tips
*   **Read the Execution Plan**: Expect exam scenario questions where you are shown an `EXPLAIN` output and asked to identify the performance problem. Look for: `Seq Scan` on large tables (missing index), very high row estimates (stale statistics — run `ANALYZE`), and nested loop JOINs on unindexed columns (add an index on the JOIN column).
*   **Cloud SQL Query Insights**: Know that this tool provides per-query metrics including execution count, average latency, bytes processed, and the ability to view the execution plan for any captured query. It is the exam answer for "how do you identify which query is causing high database CPU without modifying application code?"
*   **Index Types**: Know when to use different index types. B-tree (default) for equality and range queries. GIN index for full-text search and array containment queries in PostgreSQL. Composite indexes for multi-column WHERE clauses — column order in the index matters (put the most selective column first).
*   **Cloud Spanner Performance**: Spanner uses its own query optimizer. Performance problems in Spanner are often caused by: full table scans (missing secondary index), hotspot writes (sequential primary key — use UUIDs), or cross-region read latency (use stale reads for non-critical reads). Spanner's `EXPLAIN` output can be viewed in the Cloud Spanner Studio.
*   **Study Resource:** The official GCP Query Insights documentation is the exam reference for this module: [Cloud SQL Query Insights – Google Cloud](https://cloud.google.com/sql/docs/postgres/using-query-insights). The freeCodeCamp course covers SQL query optimization fundamentals: [SQL and Database Administration – freeCodeCamp](https://www.youtube.com/watch?v=HXV3zeQKqGY).
