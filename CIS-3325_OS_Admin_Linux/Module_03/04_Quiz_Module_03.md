### Question 1

A Linux administrator needs to locate the configuration file for the SSH server. According to the Filesystem Hierarchy Standard, in which directory should this file be found?

A. `/var/ssh/`
B. `/usr/bin/`
C. `/etc/ssh/`
D. `/opt/ssh/`

**Correct Answer: C**

**Distractor Analysis**:

- **A (`/var/ssh/`)** is incorrect. `/var` holds variable runtime data — logs, databases, queues. Configuration files do not live in `/var`.
- **B (`/usr/bin/`)** is incorrect. `/usr/bin` holds user-executable binaries, not configuration files.
- **C (`/etc/ssh/`)** is correct. All system-wide configuration files live under `/etc` per the FHS. The SSH server configuration file is `/etc/ssh/sshd_config`.
- **D (`/opt/ssh/`)** is incorrect. `/opt` is for third-party optional software packages that are installed outside the package manager. SSH is a standard system package and its configuration follows the FHS convention in `/etc`.

### Question 2

A developer wants to understand what type of data is stored in `/proc/cpuinfo`. Which of the following best describes the `/proc` filesystem?

A. A filesystem containing compiled CPU driver binaries.
B. A virtual filesystem generated at runtime by the kernel containing process and hardware information.
C. A filesystem where CPU firmware updates are stored permanently on disk.
D. A filesystem containing the source code for kernel modules.

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. `/proc` contains no compiled binaries. Drivers and kernel modules are stored in `/lib/modules/`.
- **B** is correct. `/proc` is a virtual filesystem (procfs) — nothing in it is stored on physical disk. It is generated by the kernel at runtime and exposes process information (`/proc/PID/`) and hardware statistics (`/proc/cpuinfo`, `/proc/meminfo`).
- **C** is incorrect. Firmware is stored in `/lib/firmware/`, not `/proc`. `/proc/cpuinfo` is read-only runtime information.
- **D** is incorrect. Kernel module source files are not stored on a running system in this way. `/proc` exposes runtime data, not source code.

### Question 3

An administrator wants to watch new entries being written to `/var/log/auth.log` in real time as users attempt to log in. Which command accomplishes this?

A. `cat -f /var/log/auth.log`
B. `head -f /var/log/auth.log`
C. `less -f /var/log/auth.log`
D. `tail -f /var/log/auth.log`

**Correct Answer: D**

**Distractor Analysis**:

- **A (`cat -f`)** is incorrect. `cat` does not have a `-f` (follow) flag. `cat` reads a file from beginning to end and exits.
- **B (`head -f`)** is incorrect. `head` does not have a `-f` flag. `head` displays the first N lines and exits.
- **C (`less -f`)** is incorrect. While `less` has a follow mode (`F` key inside `less`, not `-f` on the command line), `tail -f` is the standard and expected tool for real-time log monitoring.
- **D (`tail -f`)** is correct. `tail -f` opens the file, prints the last 10 lines, then continues watching for new lines and prints them as they are appended. Press `Ctrl+C` to stop.

### Question 4

Which directory contains device files such as `/dev/sda` (the first hard drive) and `/dev/null`?

A. `/sys`
B. `/proc`
C. `/dev`
D. `/mnt`

**Correct Answer: C**

**Distractor Analysis**:

- **A (`/sys`)** is incorrect. `/sys` (sysfs) is a virtual filesystem exposing kernel objects and hardware parameters, but the actual device files used by the system are in `/dev`.
- **B (`/proc`)** is incorrect. `/proc` exposes process and kernel runtime information. It does not contain device files.
- **C (`/dev`)** is correct. The device files directory. Everything from hard drives (`/dev/sda`) to terminals (`/dev/tty`) to the null device (`/dev/null`) to random number generators (`/dev/random`) lives in `/dev`.
- **D (`/mnt`)** is incorrect. `/mnt` is a directory for mounting filesystems temporarily — it holds mount points, not device files.

### Question 5

An administrator runs `find /var/log -type f -size +50M`. What will this command return?

A. All files and directories in `/var/log` that are smaller than 50 MB.
B. All regular files in `/var/log` that are larger than 50 MB.
C. All files in `/var/log` modified in the last 50 minutes.
D. All files in `/var/log` with names containing "50M."

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. The `+` before a size value means "greater than." `-` would mean "less than." No prefix would mean "exactly."
- **B** is correct. `-type f` restricts results to regular files (not directories or symlinks). `-size +50M` means larger than 50 megabytes.
- **C** is incorrect. Size and modification time are different criteria. `-mmin -50` would find files modified in the last 50 minutes; `-size +50M` finds files by size.
- **D** is incorrect. `-size` does not search file names. That would be `-name "*50M*"`.

### Question 6

A system administrator pipes the output of `ls -la /etc` to `wc -l`. What does the result represent?

A. The total size in bytes of all files in `/etc`.
B. The number of lines in the `ls -la` output, which approximates the number of items in `/etc`.
C. The number of words in the `/etc` directory listing.
D. The number of hidden files in `/etc`.

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. `wc -l` counts lines, not bytes. `wc -c` counts bytes, `wc -w` counts words.
- **B** is correct. `ls -la` outputs one line per file/directory, plus a "total" header line. `wc -l` counts all of those lines, giving approximately the number of entries in `/etc` plus one.
- **C** is incorrect. `wc -w` counts words. `wc -l` counts lines.
- **D** is incorrect. `ls -la` shows all files (including hidden), but `wc -l` counts all output lines — both hidden and non-hidden entries. To count only hidden files, you would need to filter the output with `grep`.

### Question 7

Which command creates the file `output.txt` containing only the error messages from a `find` command while silently discarding normal output?

A. `find / -name "*.conf" > output.txt`
B. `find / -name "*.conf" 2> output.txt`
C. `find / -name "*.conf" 1> output.txt`
D. `find / -name "*.conf" | output.txt`

**Correct Answer: B**

**Distractor Analysis**:

- **A (`> output.txt`)** is incorrect. `>` redirects stdout (file descriptor 1) — the normal search results. Error messages going to stderr (file descriptor 2) still appear on the terminal.
- **B (`2> output.txt`)** is correct. `2>` redirects stderr (file descriptor 2) to the file. Normal output still goes to the terminal. This captures error messages like "Permission denied" while displaying actual find results normally.
- **C (`1> output.txt`)** is incorrect. `1>` explicitly redirects stdout, which is the same as `>`. This saves normal results to the file and leaves errors on screen — the opposite of what was asked.
- **D (`| output.txt`)** is incorrect. The pipe `|` connects stdout to the stdin of another command. `output.txt` is a filename, not a command. This would fail with an error.

### Question 8

An administrator runs `ls -la /home | tee homelist.txt`. What is the result?

A. The output of `ls -la /home` is written to `homelist.txt` only, with nothing displayed on screen.
B. The output of `ls -la /home` is displayed on screen and simultaneously written to `homelist.txt`.
C. The output of `ls -la /home` is read from `homelist.txt` and displayed on screen.
D. `tee` compresses the output and saves it to `homelist.txt`.

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. This describes plain `> homelist.txt` redirection. `tee` specifically preserves the screen display while also writing to the file — that is its entire purpose.
- **B** is correct. `tee` reads stdin, writes it to the named file, AND passes it through to stdout so it still appears on screen. This is useful when you want to both see output and save it simultaneously.
- **C** is incorrect. This reverses the data flow. `tee` does not read from the file — the file is the output destination.
- **D** is incorrect. `tee` does not compress anything. It is a simple T-junction for data streams.

### Question 9

A Linux administrator runs `find /tmp -name "session_*"`. Which of the following file naming patterns would be matched by this command?

A. Only files named exactly `session_`
B. Files whose names begin with `session_` followed by any characters
C. Files whose names contain `session_` anywhere in the name
D. Files named `session` followed by exactly one character

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. The `*` wildcard in `-name` patterns matches zero or more characters. A file named exactly `session_` would match (zero characters after the underscore), but so would `session_abc`, `session_12345`, and so on.
- **B** is correct. In the `-name` option of `find`, `*` is a glob wildcard matching any string of zero or more characters. `session_*` matches any filename starting with `session_`.
- **C** is incorrect. `session_*` only matches names that START with `session_`. To match names containing `session_` anywhere, the pattern would need to be `*session_*`.
- **D** is incorrect. The single-character wildcard in glob patterns is `?`, not `*`. `session_?` would match exactly one character after the underscore.

### Question 10

According to the FHS, which directory is the correct location for log files generated by system services?

A. `/tmp`
B. `/etc/logs`
C. `/var/log`
D. `/usr/log`

**Correct Answer: C**

**Distractor Analysis**:

- **A (`/tmp`)** is incorrect. `/tmp` holds temporary files that are cleared at reboot. Log files need to persist — they are an audit and troubleshooting resource.
- **B (`/etc/logs`)** is incorrect. `/etc` contains configuration files, not runtime data like logs. There is no `/etc/logs` directory in the FHS.
- **C (`/var/log`)** is correct. `/var` holds variable data that changes during system operation — including logs, which grow continuously. The FHS specifies `/var/log` as the standard log directory.
- **D (`/usr/log`)** is incorrect. `/usr` contains user programs, libraries, and static support files. It is not used for runtime data like logs. There is no `/usr/log` directory in the FHS.
