### Task 3b: Scenario matching

Match each scenario below to the guiding principle it most directly illustrates. Write the principle name next to each scenario. (Each principle is used only once.)

**Scenario A:** A new ITSM director proposes rebuilding the entire ticketing system from scratch. A senior analyst recommends auditing the current system first, identifying what is working well, and preserving those elements in any new design.

Guiding principle: _______________

**Scenario B:** A change management team is adding eight additional approval steps to the change process. A process owner reviews the steps and determines that three of them are redundant and have never blocked a change from proceeding. She recommends removing the three steps.

Guiding principle: _______________

**Scenario C:** An IT department builds a new self-service portal without consulting the users who will use it. After launch, adoption is 12%. A retrospective reveals that users wanted a feature the portal does not have.

Guiding principle: _______________

**Scenario D:** A service manager wants to deploy a new monitoring tool to the network team only. A systems engineer points out that network events affect applications and databases — the tool should be rolled out to all infrastructure teams simultaneously so incidents can be correlated across domains.

Guiding principle: _______________

**Scenario E:** An IT organization deploys a large, multi-year service transformation in a single big-bang project. The project fails because requirements changed during the three-year delivery period and the delivered system does not meet current needs.

Guiding principle: _______________
