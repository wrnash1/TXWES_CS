### Introduction
Welcome to **Module 15 - Technical Management Practices: Monitoring and Event Management**! Monitoring and Event Management is the ITIL 4 practice that ensures services and infrastructure are continuously observed, and that events indicating conditions of significance are detected, filtered, and responded to appropriately. Without effective monitoring, the organization cannot proactively prevent incidents, maintain service quality, or demonstrate compliance with agreed service levels.

As a student, you will learn the definitions of events, alerts, and the three event types (informational, warning, and exception), understand how monitoring enables proactive service management, and explore how Monitoring and Event Management connects to Incident Management, Problem Management, and other practices. Make sure to complete the checklist and review the glossary terms before beginning the lab activity.

### 1. High-Yield Glossary
Review these essential definitions carefully. The ITIL 4 Foundation exam expects you to know these concepts precisely:

*   **Monitoring and Event Management**: The ITIL 4 practice whose purpose is to systematically observe services and service components, and record and report selected changes of state identified as events. It enables the organization to detect conditions of significance — both potential problems and opportunities — and respond before they escalate into major disruptions.
*   **Event**: Any change of state that has significance for the management of a service or other configuration item. Not every change of state is significant — Monitoring and Event Management filters events to identify those that require a response.
*   **Informational Event**: An event that does not require action but is recorded for reference or future analysis. Example: a user successfully logged into an application. Informational events provide baseline data for trend analysis and capacity planning.
*   **Warning Event**: An event that indicates a threshold is being approached or a service is operating near the boundary of acceptable performance. Warning events signal that action may be needed soon to prevent a degradation or failure. Example: disk usage reaching 80% of capacity.
*   **Exception Event**: An event that indicates a service or component has crossed an acceptable threshold and requires immediate action. Exception events typically trigger the creation of an incident record or alert an operations team. Example: a server's CPU utilization has been at 100% for 10 minutes.
*   **Alert**: A notification generated by a monitoring tool when a defined threshold or condition is met. Alerts are the mechanism by which monitoring tools communicate events to human operators or automated systems. Not all alerts require the same level of response — effective alert management filters noise and prioritizes actionable alerts.
*   **Monitoring**: The repeated observation of a system, service, or component to detect changes in its condition or performance over time. Monitoring generates the raw data from which events are identified and classified.

### 2. Certification Exam Tips
*   **Three Event Types Are Testable:** The exam tests all three event types — informational, warning, and exception — by name and by scenario. Be able to identify which type applies in a given situation.
*   **Events Are Not All Incidents:** A common exam trap treats every event as requiring incident management. Informational events require no action. Warning events may trigger preventive action. Only exception events typically generate incidents. Know the filter.
*   **Monitoring Enables Proactive Management:** The exam tests that Monitoring and Event Management enables the organization to detect and address potential failures before they cause service disruptions — this is the proactive value of the practice.
*   **Monitoring and Event Management Feeds Other Practices:** Events can trigger Incident Management (exception events), Problem Management (pattern of warning events), Change Enablement (capacity trends requiring infrastructure changes), and Continual Improvement (performance baseline data).
*   **Alert Fatigue Is a Real Risk:** ITIL 4 acknowledges that poorly tuned monitoring generates excessive alerts that overwhelm operations teams. Effective monitoring requires alert threshold management and noise reduction.

### Lab & Command Integration
In this week's hands-on lab, you will apply these concepts in the following activities:
*   **Classify a set of monitoring alerts**: Given fifteen sample monitoring alerts from a mock operations dashboard, classify each as informational, warning, or exception, and identify which require action, which require a watch, and which require no response.
*   **Design a monitoring threshold policy**: For a given server profile (CPU, memory, disk, network), define informational, warning, and exception threshold values for each metric and justify the thresholds using ITIL 4 Monitoring and Event Management principles.
*   **Map event-to-practice handoffs**: For five sample events (one informational, two warnings, two exceptions), trace how each event should be handled — including which other ITIL 4 practices should be triggered and what the expected response looks like.
