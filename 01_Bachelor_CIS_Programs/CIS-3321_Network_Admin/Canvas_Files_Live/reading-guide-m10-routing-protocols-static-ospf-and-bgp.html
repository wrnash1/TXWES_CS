Introduction

Module 10 covers how routers actually decide where to send traffic: static routes configured by hand, and the two dynamic routing protocols most heavily tested on the Network+ exam — OSPF (used inside an organization) and BGP (used to route the internet itself). The exam tests routing concepts and protocol characteristics under Domain 1: Networking Concepts and Domain 2: Network Implementation. This reading guide directly supports the Module 10 Lab, Discussion, and Quiz.

1. Core Vocabulary

  • Static route — a manually configured route entry that does not change unless an administrator edits it. Reliable and predictable, but does not adapt automatically to link failures or topology changes.

  • Dynamic routing protocol — a protocol that allows routers to automatically discover, share, and adapt routes based on real-time network conditions (e.g., OSPF, BGP, EIGRP).

  • Administrative Distance (AD) — a value (0–255) representing how trustworthy a route source is; when a router learns the same destination from multiple sources, it prefers the route with the lowest AD. Directly connected routes = 0, static routes = 1, OSPF = 110, BGP (external) = 20.

  • Metric — the value a routing protocol uses to choose the best path among multiple routes learned from the same protocol (e.g., OSPF cost, BGP path attributes). AD chooses between protocols; metric chooses within a protocol.

  • Convergence — the state where all routers in a network have consistent, up-to-date routing information after a topology change. Faster convergence means less time with black-holed or looped traffic after a failure.

  • Interior Gateway Protocol (IGP) — a routing protocol used within a single autonomous system (organization), such as OSPF. Exterior Gateway Protocol (EGP) — a routing protocol used between autonomous systems, such as BGP.

  • Autonomous System (AS) — a network or group of networks under a single administrative authority, identified on the internet by a unique AS Number (ASN) used by BGP.

  • Link-state vs. distance-vector — link-state protocols (OSPF) build a complete map of the network topology and calculate the best path themselves (Dijkstra's SPF algorithm); distance-vector protocols share only "distance and direction" information learned secondhand from neighbors.

2. Static Routing

Static routes are configured with a destination network, subnet mask, and next-hop address (or exit interface):

Router(config)# ip route 192.168.20.0 255.255.255.0 10.0.0.2

A default route (ip route 0.0.0.0 0.0.0.0 <next-hop>) matches any destination not found elsewhere in the routing table and is commonly used at the network edge to point toward the ISP.

When static routing is appropriate: small networks, stub networks with only one exit path, or as a backup/floating static route (configured with a higher AD than the primary dynamic route so it is only used if the dynamic route fails).

Limitations: does not scale to large or frequently changing topologies, requires manual reconfiguration for every topology change, and has no automatic failure detection beyond the interface going down.

3. OSPF (Open Shortest Path First)

OSPF is a link-state IGP, widely used inside enterprise networks, and heavily tested on the Network+ exam.

  • Operation: OSPF routers discover neighbors via Hello packets (multicast 224.0.0.5), exchange Link-State Advertisements (LSAs) to build an identical topology database (the Link-State Database), and each router independently runs the Shortest Path First (Dijkstra) algorithm to calculate its own best routes.

  • Areas: OSPF divides a network into areas to limit the size of the topology database each router must maintain. Area 0 (the backbone area) is mandatory in any multi-area OSPF design; all other areas must connect to Area 0, directly or through a virtual link.

  • Cost: OSPF's metric is cost, calculated by default as reference bandwidth (100 Mbps) / interface bandwidth. Lower cost is preferred. Faster links have lower cost and are therefore preferred paths.

  • Router roles in multi-area OSPF: an Area Border Router (ABR) connects two or more areas; an Autonomous System Boundary Router (ASBR) connects OSPF to an external routing domain (e.g., a different routing protocol or a static/default route redistributed into OSPF).

  • Why OSPF over RIP: OSPF converges far faster than legacy distance-vector protocols like RIP, supports VLSM/CIDR properly, and scales to large networks through areas. RIP's hop-count metric (max 15 hops) and slow convergence make it unsuitable for anything beyond very small, simple networks.

4. BGP (Border Gateway Protocol)

BGP is the EGP that runs the global internet — it is the only protocol that connects autonomous systems together at internet scale.

  • eBGP vs. iBGP: External BGP (eBGP) runs between routers in different autonomous systems (e.g., your organization's edge router and your ISP's router). Internal BGP (iBGP) runs between routers within the same autonomous system to carry BGP-learned routes across it.

  • Path selection: unlike OSPF's single numeric cost, BGP selects the best path using an ordered list of path attributes — the most commonly tested being AS-Path length (fewer autonomous systems traversed is generally preferred) and Local Preference (a value set by an organization to prefer one outbound path over another).

  • Why BGP does not use a simple metric: internet-scale routing decisions often reflect business relationships (peering agreements, transit contracts) rather than pure technical shortest-path logic — BGP's attribute-based selection allows policy, not just distance, to drive routing decisions.

  • BGP and multihoming: an organization connected to two different ISPs (multihoming) uses BGP to advertise its address space to both providers and to select or influence which provider's path is preferred for outbound traffic, and to fail over automatically if one ISP connection goes down.

5. Administrative Distance Reference Table

Route Source Default Administrative Distance
Directly connected 0
Static route 1
eBGP 20
OSPF 110
RIP 120
iBGP 200

If a router learns a route to the same destination network via both a static route and OSPF, it installs the static route in the routing table (AD 1 beats AD 110) — regardless of which route is actually "better" by hop count or bandwidth. This is a frequently tested exam scenario.

6. Static vs. OSPF vs. BGP Comparison

Characteristic Static OSPF BGP
Type Manual Dynamic, link-state, IGP Dynamic, path-vector, EGP
Scope Any size, manually maintained Single autonomous system Between autonomous systems
Convergence None (manual) Fast Slower, policy-driven
Decision basis Administrator-defined Cost (bandwidth-based) Path attributes (policy-based)
Typical use Small/stub networks, backup routes Enterprise internal routing Internet backbone, multihoming

7. Exam Tips for Module 10

  • Memorize the Administrative Distance table — especially that a static route (AD 1) always wins over OSPF (AD 110) for the same destination, even if OSPF's path is technically better.

  • Know that OSPF requires Area 0 (the backbone) in any multi-area design, and that all other areas must connect to it.

  • Distinguish AD (chooses between different protocols) from metric (chooses between routes within the same protocol) — this distinction is a common exam distractor.

  • Know that BGP is the only protocol that runs between autonomous systems (EGP), while OSPF, RIP, and EIGRP all run within one (IGP).
