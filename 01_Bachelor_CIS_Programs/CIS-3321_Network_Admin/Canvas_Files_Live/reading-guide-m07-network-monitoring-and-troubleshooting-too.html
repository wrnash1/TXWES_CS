Introduction

Module 07 shifts from network design to network operations: how administrators verify connectivity, diagnose failures, and monitor a live network. The CompTIA Network+ exam tests command-line diagnostic tools and monitoring protocols under Domain 5: Network Troubleshooting. This reading guide organizes the tools, protocols, and exam tips for the Module 07 video lectures, and directly supports the Module 07 Lab (ping, tracert, nslookup, netstat, Wireshark) and Discussion.

1. Core Vocabulary

  • ICMP (Internet Control Message Protocol) — the Layer 3 protocol used by ping and traceroute/tracert to test reachability and report errors. ICMP has no port number; it is identified by protocol number 1 in the IP header.

  • TTL (Time to Live) — a field in the IP header that decrements by one at each router hop; when it reaches zero, the packet is discarded and the router returns an ICMP "Time Exceeded" message. TTL is the mechanism traceroute exploits to map a path hop by hop.

  • RTT (Round-Trip Time) — the time for a packet to travel to a destination and back, reported by ping and traceroute in milliseconds. High or highly variable RTT (jitter) affects real-time applications like VoIP and video conferencing.

  • Divide-and-conquer troubleshooting — a methodology that tests connectivity at a midpoint of the path (e.g., the default gateway) to isolate whether a fault lies on the local segment or beyond it, narrowing the search space faster than testing end-to-end first.

  • Packet capture (packet sniffing) — recording raw frames/packets as they cross an interface, typically with Wireshark or tcpdump, for detailed protocol-level analysis.

  • Display filter vs. capture filter — a capture filter (BPF syntax) limits what Wireshark records at capture time; a display filter (Wireshark's own syntax, e.g., tcp.port == 443) limits what is shown from an already-captured file without discarding data.

  • SNMP (Simple Network Management Protocol) — a protocol (UDP 161 for queries, UDP 162 for traps) used to monitor and manage network devices, pulling metrics (SNMP GET) or receiving unsolicited alerts (SNMP traps) from devices.

  • Syslog — a standard (UDP/TCP 514) for forwarding log messages from network devices to a centralized logging server, enabling correlation and long-term retention of event data across the network.

  • NetFlow / sFlow — protocols that export traffic flow summaries (source/destination, ports, byte counts) from routers and switches to a collector for bandwidth analysis and anomaly detection, without capturing full packet contents.

3. Interpreting ping and traceroute Output

ping and tracert/traceroute are the two most heavily tested command-line tools on the Network+ exam. Key interpretation rules:

  • A successful ping to 127.0.0.1 (loopback) confirms the local TCP/IP stack is installed and functioning — it never leaves the network interface card.

  • Default starting TTL values are commonly 128 (Windows), 64 (Linux/macOS), and 255 (some network devices/Cisco IOS). Subtracting the received TTL from the nearest standard starting value estimates the hop count to a destination.

  • Three asterisks (***) at a single hop in a traceroute mean that hop did not respond to the probe — commonly because the router is configured to not respond to ICMP (rate-limiting or security policy), not necessarily that the path is broken. If later hops respond normally, traffic is still being forwarded through that hop.

  • A large, sudden RTT increase between two consecutive hops usually indicates a long-distance or congested link between those two routers (e.g., a transoceanic or inter-carrier hop), not a fault.

4. netstat State Reference

State Meaning
LISTENING A local process is bound to a port, waiting for incoming connections
ESTABLISHED An active, fully connected TCP session exists
TIME_WAIT The connection has closed but the OS is holding the socket briefly to catch delayed packets
CLOSE_WAIT The remote side has closed the connection; the local application has not yet closed its end

A listening port on an unexpected high-numbered port (e.g., TCP 4444, commonly associated with certain remote-access tools) on a workstation that should not be running any server software is a classic indicator of compromise worth investigating with a process-mapping flag (netstat -anb on Windows, run elevated).

5. Wireshark Fundamentals

  • Capture setup: select the correct interface (the one showing live traffic activity) before starting a capture; capturing on the wrong interface yields an empty or irrelevant capture.

  • The TCP three-way handshake appears in a capture as three consecutive packets: SYN (SYN=1, ACK=0) from the client, SYN-ACK (SYN=1, ACK=1) from the server, and ACK (SYN=0, ACK=1) from the client. The filter tcp.flags.syn == 1 isolates connection-establishment attempts.

  • DNS in a capture appears as UDP port 53 traffic by default (TCP 53 is used for zone transfers and responses too large for a single UDP datagram, and by DNS-over-TCP/DoT/DoH implementations). A query and its response share the same Transaction ID, allowing a client to match responses to outstanding queries even under concurrent lookups.

  • Common display filters:

Filter Shows
ip.addr == 192.168.1.50 Traffic where 192.168.1.50 is source OR destination
tcp.port == 443 TCP traffic on port 443 (HTTPS)
icmp ICMP traffic (ping)
dns.flags.response == 1 DNS response packets only
ip.addr == 192.168.1.10 && ip.addr == 10.0.0.1 Traffic specifically between two given hosts

6. Monitoring Protocols Comparison

Protocol Transport Purpose Push or Pull
SNMP GET UDP 161 Manager queries a device for current metric values Pull
SNMP Trap UDP 162 Device sends an unsolicited alert to the manager Push
Syslog UDP/TCP 514 Device forwards log/event messages to a central server Push
NetFlow/sFlow UDP (varies by vendor) Device exports traffic flow summaries to a collector Push

For a WAN link failure scenario, the typical design pairs syslog (to capture the event details for later analysis) with an SNMP trap (to trigger an immediate alert to the operations team) — using both gives both historical record-keeping and real-time notification.

7. Exam Tips for Module 07

  • Know the default TTL values (64, 128, 255) cold — TTL/hop-count questions are common and calculation-based.

  • Distinguish "no response" from "path broken" for traceroute asterisks — this is a frequently tested distractor.

  • Memorize the SNMP port pair (161 query / 162 trap) and the syslog port (514) — these appear on both Network+ and Security+ style questions.

  • Be able to identify the three TCP handshake packets by their flag combinations, not just by position in a list.
