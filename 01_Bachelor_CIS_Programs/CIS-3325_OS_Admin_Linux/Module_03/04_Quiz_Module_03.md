### Question 1

A Linux administrator needs to locate the configuration file for the SSH server. According to the Filesystem Hierarchy Standard, in which directory should this file be found?

A. `/var/ssh/`
B. `/usr/bin/`
C. `/etc/ssh/`
D. `/opt/ssh/`

**Correct Answer: C**

**Distractor Analysis**:

- **A (`/var/ssh/`)** is incorrect. `/var` holds variable runtime data — logs, databases, queues. Configuration files do not live in `/var`.
- **B (`/usr/bin/`)** is incorrect. `/usr/bin` holds user-executable binaries, not configuration files.
- **C (`/etc/ssh/`)** is correct. All system-wide configuration files live under `/etc` per the FHS. The SSH server configuration file is `/etc/ssh/sshd_config`.
- **D (`/opt/ssh/`)** is incorrect. `/opt` is for third-party optional software packages that are installed outside the package manager. SSH is a standard system package and its configuration follows the FHS convention in `/etc`.

### Question 2

A developer wants to understand what type of data is stored in `/proc/cpuinfo`. Which of the following best describes the `/proc` filesystem?

A. A filesystem containing compiled CPU driver binaries.
B. A virtual filesystem generated at runtime by the kernel containing process and hardware information.
C. A filesystem where CPU firmware updates are stored permanently on disk.
D. A filesystem containing the source code for kernel modules.

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. `/proc` contains no compiled binaries. Drivers and kernel modules are stored in `/lib/modules/`.
- **B** is correct. `/proc` is a virtual filesystem (procfs) — nothing in it is stored on physical disk. It is generated by the kernel at runtime and exposes process information (`/proc/PID/`) and hardware statistics (`/proc/cpuinfo`, `/proc/meminfo`).
- **C** is incorrect. Firmware is stored in `/lib/firmware/`, not `/proc`. `/proc/cpuinfo` is read-only runtime information.
- **D** is incorrect. Kernel module source files are not stored on a running system in this way. `/proc` exposes runtime data, not source code.

### Question 3

An administrator wants to watch new entries being written to `/var/log/auth.log` in real time as users attempt to log in. Which command accomplishes this?

A. `cat -f /var/log/auth.log`
B. `head -f /var/log/auth.log`
C. `less -f /var/log/auth.log`
D. `tail -f /var/log/auth.log`

**Correct Answer: D**

**Distractor Analysis**:

- **A (`cat -f`)** is incorrect. `cat` does not have a `-f` (follow) flag. `cat` reads a file from beginning to end and exits.
- **B (`head -f`)** is incorrect. `head` does not have a `-f` flag. `head` displays the first N lines and exits.
- **C (`less -f`)** is incorrect. While `less` has a follow mode (`F` key inside `less`, not `-f` on the command line), `tail -f` is the standard and expected tool for real-time log monitoring.
- **D (`tail -f`)** is correct. `tail -f` opens the file, prints the last 10 lines, then continues watching for new lines and prints them as they are appended. Press `Ctrl+C` to stop.

### Question 4

Which directory contains device files such as `/dev/sda` (the first hard drive) and `/dev/null`?

A. `/sys`
B. `/proc`
C. `/dev`
D. `/mnt`

**Correct Answer: C**

**Distractor Analysis**:

- **A (`/sys`)** is incorrect. `/sys` (sysfs) is a virtual filesystem exposing kernel objects and hardware parameters, but the actual device files used by the system are in `/dev`.
- **B (`/proc`)** is incorrect. `/proc` exposes process and kernel runtime information. It does not contain device files.
- **C (`/dev`)** is correct. The device files directory. Everything from hard drives (`/dev/sda`) to terminals (`/dev/tty`) to the null device (`/dev/null`) to random number generators (`/dev/random`) lives in `/dev`.
- **D (`/mnt`)** is incorrect. `/mnt` is a directory for mounting filesystems temporarily — it holds mount points, not device files.

### Question 5

An administrator runs `find /var/log -type f -size +50M`. What will this command return?

A. All files and directories in `/var/log` that are smaller than 50 MB.
B. All regular files in `/var/log` that are larger than 50 MB.
C. All files in `/var/log` modified in the last 50 minutes.
D. All files in `/var/log` with names containing "50M."

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. The `+` before a size value means "greater than." `-` would mean "less than." No prefix would mean "exactly."
- **B** is correct. `-type f` restricts results to regular files (not directories or symlinks). `-size +50M` means larger than 50 megabytes.
- **C** is incorrect. Size and modification time are different criteria. `-mmin -50` would find files modified in the last 50 minutes; `-size +50M` finds files by size.
- **D** is incorrect. `-size` does not search file names. That would be `-name "*50M*"`.

### Question 6

A system administrator pipes the output of `ls -la /etc` to `wc -l`. What does the result represent?

A. The total size in bytes of all files in `/etc`.
B. The number of lines in the `ls -la` output, which approximates the number of items in `/etc`.
C. The number of words in the `/etc` directory listing.
D. The number of hidden files in `/etc`.

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. `wc -l` counts lines, not bytes. `wc -c` counts bytes, `wc -w` counts words.
- **B** is correct. `ls -la` outputs one line per file/directory, plus a "total" header line. `wc -l` counts all of those lines, giving approximately the number of entries in `/etc` plus one.
- **C** is incorrect. `wc -w` counts words. `wc -l` counts lines.
- **D** is incorrect. `ls -la` shows all files (including hidden), but `wc -l` counts all output lines — both hidden and non-hidden entries. To count only hidden files, you would need to filter the output with `grep`.

### Question 7

Which command creates the file `output.txt` containing only the error messages from a `find` command while silently discarding normal output?

A. `find / -name "*.conf" > output.txt`
B. `find / -name "*.conf" 2> output.txt`
C. `find / -name "*.conf" 1> output.txt`
D. `find / -name "*.conf" | output.txt`

**Correct Answer: B**

**Distractor Analysis**:

- **A (`> output.txt`)** is incorrect. `>` redirects stdout (file descriptor 1) — the normal search results. Error messages going to stderr (file descriptor 2) still appear on the terminal.
- **B (`2> output.txt`)** is correct. `2>` redirects stderr (file descriptor 2) to the file. Normal output still goes to the terminal. This captures error messages like "Permission denied" while displaying actual find results normally.
- **C (`1> output.txt`)** is incorrect. `1>` explicitly redirects stdout, which is the same as `>`. This saves normal results to the file and leaves errors on screen — the opposite of what was asked.
- **D (`| output.txt`)** is incorrect. The pipe `|` connects stdout to the stdin of another command. `output.txt` is a filename, not a command. This would fail with an error.

### Question 8

An administrator runs `ls -la /home | tee homelist.txt`. What is the result?

A. The output of `ls -la /home` is written to `homelist.txt` only, with nothing displayed on screen.
B. The output of `ls -la /home` is displayed on screen and simultaneously written to `homelist.txt`.
C. The output of `ls -la /home` is read from `homelist.txt` and displayed on screen.
D. `tee` compresses the output and saves it to `homelist.txt`.

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. This describes plain `> homelist.txt` redirection. `tee` specifically preserves the screen display while also writing to the file — that is its entire purpose.
- **B** is correct. `tee` reads stdin, writes it to the named file, AND passes it through to stdout so it still appears on screen. This is useful when you want to both see output and save it simultaneously.
- **C** is incorrect. This reverses the data flow. `tee` does not read from the file — the file is the output destination.
- **D** is incorrect. `tee` does not compress anything. It is a simple T-junction for data streams.

### Question 9

A Linux administrator runs `find /tmp -name "session_*"`. Which of the following file naming patterns would be matched by this command?

A. Only files named exactly `session_`
B. Files whose names begin with `session_` followed by any characters
C. Files whose names contain `session_` anywhere in the name
D. Files named `session` followed by exactly one character

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. The `*` wildcard in `-name` patterns matches zero or more characters. A file named exactly `session_` would match (zero characters after the underscore), but so would `session_abc`, `session_12345`, and so on.
- **B** is correct. In the `-name` option of `find`, `*` is a glob wildcard matching any string of zero or more characters. `session_*` matches any filename starting with `session_`.
- **C** is incorrect. `session_*` only matches names that START with `session_`. To match names containing `session_` anywhere, the pattern would need to be `*session_*`.
- **D** is incorrect. The single-character wildcard in glob patterns is `?`, not `*`. `session_?` would match exactly one character after the underscore.

### Question 10

According to the FHS, which directory is the correct location for log files generated by system services?

A. `/tmp`
B. `/etc/logs`
C. `/var/log`
D. `/usr/log`

**Correct Answer: C**

**Distractor Analysis**:

- **A (`/tmp`)** is incorrect. `/tmp` holds temporary files that are cleared at reboot. Log files need to persist — they are an audit and troubleshooting resource.
- **B (`/etc/logs`)** is incorrect. `/etc` contains configuration files, not runtime data like logs. There is no `/etc/logs` directory in the FHS.
- **C (`/var/log`)** is correct. `/var` holds variable data that changes during system operation — including logs, which grow continuously. The FHS specifies `/var/log` as the standard log directory.
- **D (`/usr/log`)** is incorrect. `/usr` contains user programs, libraries, and static support files. It is not used for runtime data like logs. There is no `/usr/log` directory in the FHS.

### Question 11 (5 points)

An administrator wants to search for the string "failed password" (case-insensitive) in `/var/log/auth.log` and save only the matching lines to a file called `failures.txt`. Which command accomplishes this?

A. `grep "failed password" /var/log/auth.log > failures.txt`
B. `grep -i "failed password" /var/log/auth.log > failures.txt`
C. `find /var/log/auth.log -name "failed password" > failures.txt`
D. `cat /var/log/auth.log | tee failures.txt | grep -i "failed password"`

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. Without `-i`, `grep` performs a case-sensitive match. "Failed Password" or "FAILED PASSWORD" entries would be missed.
- **B** is correct. `-i` makes the match case-insensitive, catching all capitalizations of "failed password." The `>` redirect saves only the matching lines to `failures.txt`.
- **C** is incorrect. `find` searches for files by name or attribute — it does not search file content. This command looks for a file named "failed password," which does not exist.
- **D** is incorrect. This saves the full unfiltered log to `failures.txt` before the `grep` filter is applied. Only the terminal output is filtered; the file would contain the entire log.

### Question 12 (5 points)

Which command appends the current date and time to the end of an existing file named `log.txt` without overwriting its contents?

A. `date > log.txt`
B. `date >> log.txt`
C. `date 2> log.txt`
D. `date | log.txt`

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. The `>` operator overwrites the file. Any existing content in `log.txt` would be deleted and replaced with just the date output.
- **B** is correct. The `>>` operator appends stdout to the end of the file. Existing content is preserved and the new date is added at the bottom.
- **C** is incorrect. `2>` redirects stderr, not stdout. The `date` command outputs to stdout and produces no stderr under normal operation, so `log.txt` would be created empty (or remain unchanged if it exists and no error occurred).
- **D** is incorrect. The pipe `|` connects stdout to another command's stdin. `log.txt` is a filename, not a command. This syntax is invalid and would fail.

### Question 13 (5 points)

A system administrator needs to find all `.log` files under `/var` that were modified within the last 2 days. Which `find` command is correct?

A. `find /var -name "*.log" -size -2M`
B. `find /var -type f -name "*.log" -mtime -2`
C. `find /var -type f -name "*.log" -mtime +2`
D. `find /var -name "*.log" -ctime -2`

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. `-size -2M` finds files smaller than 2 MB — it has nothing to do with modification time.
- **B** is correct. `-mtime -2` means "modified less than 2 days ago" (i.e., within the last 2 days). The minus sign means "within the last N days."
- **C** is incorrect. `-mtime +2` means "modified MORE than 2 days ago" — the opposite of what was requested. The plus sign means "older than N days."
- **D** is partially correct in intent (ctime is "change time") but `-ctime` tracks inode change time (permissions, ownership changes), not content modification time. `-mtime` is the correct predicate for content modification.

### Question 14 (5 points)

An administrator runs `command1 | command2 | command3`. In this pipeline, what does `command2` receive as its input?

A. The stderr output of `command1`.
B. The stdout output of `command1`.
C. Data read directly from disk by the pipeline manager.
D. The combined stdout and stderr of all commands.

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. By default, the pipe `|` connects only stdout of one command to stdin of the next. Stderr is not captured by the pipe unless explicitly redirected with `2>&1`.
- **B** is correct. The pipe operator sends the stdout of `command1` to the stdin of `command2`. `command2` processes that data and its stdout flows to `command3`.
- **C** is incorrect. Pipelines pass data between processes in memory (via kernel pipe buffers). No intermediate disk I/O occurs.
- **D** is incorrect. Only stdout flows through a plain pipe. To include stderr, you would need `command1 2>&1 | command2`.

### Question 15 (5 points)

Which of the following `find` options suppresses "Permission denied" error messages from appearing on the terminal?

A. `find / -name "*.sh" --no-errors`
B. `find / -name "*.sh" -silent`
C. `find / -name "*.sh" 2>/dev/null`
D. `find / -name "*.sh" 1>/dev/null`

**Correct Answer: C**

**Distractor Analysis**:

- **A** is incorrect. There is no `--no-errors` option for `find`. This would cause an error.
- **B** is incorrect. There is no `-silent` option for `find`. This would cause an error.
- **C** is correct. `2>/dev/null` redirects stderr (file descriptor 2) to `/dev/null`, discarding all error messages including "Permission denied." Normal search results still appear on the terminal.
- **D** is incorrect. `1>/dev/null` redirects stdout — the actual search results — to `/dev/null`, discarding them. Error messages would still appear on screen. This is the opposite of what was asked.

### Question 16 (5 points)

What is the correct location for kernel modules (device drivers) on a Linux system?

A. `/etc/modules`
B. `/proc/modules`
C. `/lib/modules/$(uname -r)/`
D. `/dev/modules/`

**Correct Answer: C**

**Distractor Analysis**:

- **A (`/etc/modules`)** is incorrect. `/etc/modules` is a configuration file that lists modules to load at boot — it does not contain the module files themselves.
- **B (`/proc/modules`)** is incorrect. `/proc/modules` is a virtual file that lists currently loaded modules, but it does not store the module files on disk.
- **C** is correct. Kernel module files (`.ko` files) are stored in `/lib/modules/<kernel-version>/`. The `$(uname -r)` substitution inserts the running kernel version. For example: `/lib/modules/6.5.0-21-generic/`.
- **D (`/dev/modules/`)** is incorrect. `/dev` contains device files, not kernel module binaries. There is no `/dev/modules/` directory in the FHS.

### Question 17 (5 points)

An administrator runs `wc -l /etc/passwd`. The output is `42`. What does this indicate?

A. The passwd file has 42 characters.
B. The passwd file has 42 words.
C. The passwd file has 42 lines, suggesting approximately 42 user accounts or system entries.
D. The passwd file is 42 kilobytes.

**Correct Answer: C**

**Distractor Analysis**:

- **A** is incorrect. Character count is shown by `wc -c`. The `-l` flag counts lines.
- **B** is incorrect. Word count is shown by `wc -w`. The `-l` flag counts lines.
- **C** is correct. `wc -l` counts newline characters, which equals the number of lines. Since each line in `/etc/passwd` represents one user account or system service entry, 42 lines means approximately 42 entries.
- **D** is incorrect. File size in kilobytes would be shown by `ls -lh` or `du -sh`. `wc -l` produces a line count, not a size measurement.

### Question 18 (5 points)

Which of the following commands correctly uses `find`'s `-exec` option to delete all files named `*.tmp` under `/tmp`?

A. `find /tmp -name "*.tmp" -exec rm {} ;`
B. `find /tmp -name "*.tmp" -exec rm {} \;`
C. `find /tmp -name "*.tmp" | rm`
D. `find /tmp -name "*.tmp" -delete {}`

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. The semicolon that terminates `-exec` must be escaped as `\;` (or quoted as `';'`) to prevent the shell from interpreting it as a command separator. Without the backslash, the shell consumes the `;` before `find` sees it.
- **B** is correct. `-exec rm {} \;` runs `rm` once per found file. `{}` is replaced by the filename; `\;` is the properly escaped terminator that `find` requires.
- **C** is incorrect. Piping filenames from `find` to `rm` does not work — `rm` reads filenames as command-line arguments, not from stdin. `xargs` would be needed: `find /tmp -name "*.tmp" | xargs rm`.
- **D** is incorrect. `-delete` is a valid `find` action that deletes found files, but `-delete {}` is wrong syntax. The correct usage is simply `-delete` with no argument: `find /tmp -name "*.tmp" -delete`.

### Question 19 (5 points)

A junior administrator asks what `/dev/zero` is used for. Which answer is correct?

A. It generates cryptographically secure random bytes.
B. It produces an infinite stream of null bytes (zero bytes) when read.
C. It discards all data written to it.
D. It stores the current system entropy pool.

**Correct Answer: B**

**Distractor Analysis**:

- **A** is incorrect. Cryptographically secure random bytes come from `/dev/random` (blocking) or `/dev/urandom` (non-blocking). `/dev/zero` always produces zero bytes, not random data.
- **B** is correct. `/dev/zero` is a special character device that produces an endless stream of null (zero) bytes when read. It is commonly used to overwrite files or partitions with zeros: `dd if=/dev/zero of=/dev/sdb`.
- **C** is incorrect. Discarding data written to a device describes `/dev/null` — data written to it disappears. `/dev/zero` is a data source, not a sink.
- **D** is incorrect. The entropy pool is managed by `/dev/random` and `/dev/urandom`. `/dev/zero` has no connection to entropy.

### Question 20 (5 points)

An administrator wants to view a file that is 5,000 lines long one screen at a time, with the ability to search for text and scroll both forward and backward. Which command is most appropriate?

A. `cat /path/to/file`
B. `head -5000 /path/to/file`
C. `more /path/to/file`
D. `less /path/to/file`

**Correct Answer: D**

**Distractor Analysis**:

- **A** is incorrect. `cat` dumps the entire file to the terminal at once with no pagination. A 5,000-line file would scroll off screen instantly with no way to navigate backward.
- **B** is incorrect. `head -5000` would print all 5,000 lines at once (since the file has exactly 5,000 lines), same problem as `cat`. `head` does not paginate.
- **C** is partially correct but `more` only supports forward navigation. Once you scroll past a section you cannot scroll back. It is the older, less capable alternative.
- **D** is correct. `less` is the standard pager for viewing large files. It supports forward and backward scrolling, text search with `/`, line-number jumping with `<number>G`, and handles files of any size without loading the whole file into memory.
